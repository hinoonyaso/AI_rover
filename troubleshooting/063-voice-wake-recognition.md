# 음성 호출어가 인식되지 않는 현상

- 상태: 미해결, 음성 관제 시제품 인식 품질 개선 및 실제 발화 평가 필요.
- 증상: Piper 합성 발화 4개를 기존 로컬 Whisper base 한국어 모델로 시험했을 때 모두 `로버` 호출어가 정확히 전사되지 않아 명령이 무시됐다. 이 소수 합성 표본은 실제 사용자 인식률을 대표하지 않는다.
- 확인된 원인: 음량 VAD는 발화 구간만 분리하며 호출어 판정은 STT 출력의 정확한 접두어에 의존한다. STT가 호출어를 다른 단어로 출력하면 이후 해석 단계에 도달하지 못한다. 모델·발음·마이크·소음 중 어느 요인이 지배적인지는 아직 확인되지 않았다.
- 현재 동작: 화면의 인식 문장 확인과 텍스트 시험을 제공한다. 모의 임무는 별도 확인 후 실행되며 실제 구동 명령은 제공하지 않는다. 오인식을 무조건 호출어로 받아들이는 우회는 적용하지 않았다.
- 남은 검증: 사람 발화와 무음·주변 소음·스피커 재유입의 독립 음성 표본, 호출어 오탐/미탐과 지연을 측정하고 모델·별도 호출어 검출기 변경을 비교한다. 오탐이 없는지 확인하기 전까지 실기 제어에 연결하지 않는다.

## 추가 확인: Whisper 초기 프롬프트 효과와 오탐 (2026-11-22, Claude Code)

- Piper `ko_KR-kss-medium` 합성 → sox 16kHz 변환 → 기존 `whisper-cli` + `ggml-base.bin`, `-l ko`. 스피커 재생·로봇 구동 없음. 임시 파일은 세션 scratchpad에만 둠.
- 호출어 포함 6문장: 프롬프트 없이 호출어 정확 0/6(`노버`, `로봇`, `룰 볼`, `Z로봇` 등). `--prompt "로버, 제트로버. 로버 배터리 상태 알려줘. 로버 모의 점검 시작해."` 사용 시 호출어 6/6(본문 오인식 `나이다`, `뭐 이모 취소해`는 남음).
- 같은 프롬프트로 호출어 없는 4문장 + 핑크 잡음 3초: `모의 점검 시작해.` → `로버 모의 점검 시작해.`로 **호출어가 없는데 생성됨**(오탐 1/4). 잡음 → `이곳은 제트로버.`(현재 정규식 접두어와는 불일치하지만 환각).
- 결론: 미탐의 주된 원인은 base 모델의 고유명사 편향(프롬프트로 대부분 해소). 그러나 프롬프트는 오탐을 만든다. 프롬프트 단독 적용은 안전하지 않고, 별도 호출어 검출기(예: 마이크 어레이 내장 깨우기/KWS 모델)나 푸시투토크와 비교가 필요하다. 합성 음성 소표본이며 실제 사람 발화 성능이 아니다.
- 보조 관찰: `voiceVad.js`의 `MonoResampler`는 저역 통과 필터 없이 표본을 솎아내 48kHz→16kHz에서 앨리어싱이 생길 수 있다(브라우저 경로 전용, 이 실험엔 영향 없음). 정규식은 `제트 로버`(띄어쓰기)를 받지 않는다.

## 내장 호출어(R818 "Hello Hiwonder") 전환 시험 (2026-11-22)

사용자 결정: 전사 기반 호출어 대신 마이크 보드 내장 호출어 "Hello Hiwonder"만 사용한다.

- 도구: `tools/audio/r818_wake_probe.py`(수신 프레임 전체 기록, 음성 저장·로봇 구동 없음). 포트 `/dev/serial/by-path/platform-3610000.usb-usb-0:2.1.1.1:1.0-port0`(현재 `ttyUSB0`, 다른 프로세스 미사용 확인).
- 수신 전용 90초: 핸드셰이크 180회(0.5초 주기)만 수신, 사용자가 "Hello Hiwonder" 발화했으나 다른 프레임 0.
- 확인 응답(`--ack`) 90초: 핸드셰이크 3회 후 중단(연결 성립), "Hello Hiwonder" 3회 발화에도 프레임 0, 사용자 관찰상 보드 소리·LED 반응 없음.
- 제조사 자료(Elephant `mercury_speech`): 호스트는 포트에 쓰지 않고 `{"type":"aiui_event", "content":{"result","info"}}` JSON만 읽는다. Hiwonder 문서상 기본 호출어는 "hello hiwonder"이며 언어 전환은 Hiwonder 이미지의 GUI 도구/`xf_mic_asr_offline mic_init.launch.py`가 담당한다. 호출어 설정 시리얼 명령은 공개 자료에서 찾지 못함.
- 원인 후보(미확정): ① 보드에 다른 호출어(중국어 "小幻小幻" 등) 또는 빈 호출어 자원이 설정됨, ② 2026-11-11 보드 내부 프로세스 재시작 실험 이후 보드 음성 처리 상태 이상(당시 모노 음량 저하 기록, `prd/audio-doa.md`), ③ 이벤트 송신에 호스트 측 설정 명령이 필요.
- 다음 확인: 보드 내부를 ADB로 읽기 전용 확인(`vtn/vtn.ini`·호출어 자원·`demo.log`에서 발화 시 깨우기 로그) 또는 Hiwonder `xf_mic_asr_offline` 소스 확보. 이 확인 전에는 내장 호출어 기반 음성 관제를 구현 완료로 보지 않는다.
