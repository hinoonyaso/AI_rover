# 039 — 자체 펌웨어: 게임패드 HID 리포트 해석이 틀려 중립인데 버튼이 눌린 것으로 보고 (2026-10-11)

- 상태: **해결**(레이아웃 실측 확정, 호스트 시험), 실기 재확인은 flash 후
- 관련: `firmware/rrc_m4/lib/core/src/gamepad.c`, 확장 프레임 0x23(RAW_HID), `tools/stm32_diagnostics/rrc_m4_io_test.py`

## 증상
브링업 중 게임패드 확인: 아무것도 안 눌렀는데 FUNC8이 `buttons 0x8f03, 왼쪽 스틱 −121`을 보고. 펌웨어가 함께 보내는 원시 리포트(0x23)는
`07 80 7f 80 7f 0f 00 00 00 00 00`(중립).

## 원인
`GAMEPAD_LAYOUT_DEFAULT`가 "8바이트 PS2 호환 리포트"라는 **미검증 추정**이었다(코드에 UNVERIFIED로 표시, 원시 캡처 후 표를 고치는 구조).
실제 리포트는 맨 앞에 리포트 ID `0x07`이 붙은 11바이트라 스틱·방향키·버튼이 전부 한 칸씩 밀려 있었다.

## 해결 (실측)
알려 준 순서(Y, B, A, X, L1, R1, L2, R2, SELECT, START, MODE, 방향키 4, 왼쪽 스틱 4, 오른쪽 스틱 4, L3, R3)로 눌러 원시 리포트 변화를 캡처:

| 입력 | 위치 |
|---|---|
| 왼쪽/오른쪽 스틱 | byte1·2 / byte3·4 (좌우, 상하; 0 = 왼쪽·위, 0xff = 오른쪽·아래, 중립 ~0x7f) |
| 방향키 | byte5 하위 4비트(0 위, 2 오른쪽, 4 아래, 6 왼쪽, 0x0f 중립) |
| A, B, X, Y | byte6 비트 0, 1, 3, 4 |
| L1, R1 | byte6 비트 6, 7 |
| L2, R2 | byte7 비트 0, 1 (아날로그 byte9 = L2, byte8 = R2) |
| SELECT, START, MODE | byte7 비트 2, 3, 4 |
| L3, R3 | byte7 비트 5, 6 |

`raw_buttons = byte7 | byte6 << 8`로 두고 표를 vendor FUNC8 마스크에 맞춤(A = CROSS, B = CIRCLE, X = SQUARE, Y = TRIANGLE).
같은 캡처를 호스트 시험 값으로 사용(중립 포함 28개 검사).

## 확인 못 한 것
- **L1 마스크: 0x4000으로 정함**(처음엔 문서의 0x0400을 기능 기준으로 배정). 근거: 문서의 마스크 11개 중 10개(L2·R2·SELECT·START·L3·R3·CROSS·CIRCLE·SQUARE·TRIANGLE·R1)가 원시 비트(byte7 | byte6 << 8)와
  정확히 같고, 이 수신기의 L1은 byte6 bit6 = 0x4000이며 0x0400은 그 값의 두 자리가 바뀐 꼴 → 문서 오타로 보고 vendor 펌웨어가 원시 비트를 통과시킨다고 가정.
  **미검증**: vendor 펌웨어를 올리고 L1을 눌러 FUNC8 값을 읽으면 확정(공식 PDF에는 버튼 비트 정의 없음, 호스트 SDK 참고 코드도 이 저장소에 없음).
- MODE는 vendor 마스크 목록에 없어 빈 자리 0x0010에 배정.
- 스틱 중립이 0x7f(−1)로 읽힘 — 호스트에서 작은 데드존을 두면 된다.

## 재발 방지
- 추정 레이아웃은 코드에 UNVERIFIED로 남기고, 브링업에서 원시 캡처로 확정한다(이번에도 이 구조 덕에 표만 고쳤다).
- 입력 장치 확인은 "중립에서 아무 이벤트도 없는지"부터 본다.
