# 037 — 자체 펌웨어: 전원을 완전히 껐다 켠 뒤 IMU 값이 멈춤(같은 값 반복) (2026-10-10)

- 상태: **해결**(소프트 리셋 추가 + 멈춘 값 감지, 냉간 부팅 실기 확인)
- 관련: `firmware/rrc_m4/lib/core/src/imu.c`, troubleshooting/035·036, `docs/benchmarks/navigation/encoder_odom_e4_20261010.md`

## 증상
회전 보정 재측정(E4) 도중 로봇 전원이 꺼졌다 켜진 뒤(16:26 이후 정상 종료 로그 없음, 19:01 부팅, STM32 리셋 원인 0x0e = 전원 투입),
360° 회전에서 EKF yaw가 381.9°(엔코더 358.6°)로 튐. `/imu/data_raw`가 50 Hz로 오지만 **3초 동안 값이 단 1개**
(가속도·자이로 전부 동일, 표준편차 0). 펌웨어는 I2C 읽기가 성공할 때만 IMU 프레임을 보내므로, 읽기는 성공하는데
센서 레지스터가 갱신되지 않는 상태. 멈춘 자이로 z(+0.94°/s)가 회전 동안 그대로 적분돼 +21.9° 오차.
MCU만 리셋(SWD SYSRESETREQ, IMU 전원 유지)해도 계속 멈춰 있음 → MCU 타이밍이 아니라 **센서 칩 상태** 문제.

## 원인
`try_qmi()`가 QMI8658을 **소프트 리셋 없이** 바로 CTRL1/2/3/7을 썼다. 오늘 오후의 정상 동작은 전부 아침에 vendor 펌웨어가
칩을 초기화해 둔 상태에서 MCU만 flash·리셋한 경우였고, 전원이 통째로 꺼졌다 켜진 칩을 우리 펌웨어가 처음 초기화하자 측정이 멈췄다.
vendor 바이너리(`decompiled.c` `FUN_0800b514`): 레지스터 0x60 ← 0xB0(소프트 리셋) → 0x4D가 0x80이 될 때까지 10 ms 간격 폴링 → 설정.

## 해결
1. vendor와 같은 순서: 소프트 리셋 → 0x4D == 0x80 대기(최대 100 ms) → CTRL1/2/3/7.
2. **멈춘 값 감지**: 원시 12/14바이트가 `IMU_FROZEN_SAMPLES`(25회, 0.5 s) 연속 같으면 `IMU_ERR_FROZEN` 반환 → imu_task가
   오류로 세어 10회째에 버스 복구 + 재초기화(소프트 리셋 포함). 멈춘 값이 EKF에 가짜 회전으로 들어가지 않는다(그동안 IMU 프레임 미발행).
3. 호스트 시험: 가짜 버스에 리셋 완료 신호, 소프트 리셋 후 센서 활성 확인, 25회째 감지, 값이 변하면 정상 복귀.

## 확인
flash 후 로봇 전원 완전 차단·재투입(리셋 원인 0x0e) → IMU 149프레임 전부 다른 값, 정지 자이로 −9.54/−11.94/+0.92 °/s(정상 bias와 동일).

## 재발 방지
- 센서 초기화는 "이미 초기화된 칩"이 아니라 **전원 투입 직후 칩**에서 시험한다(냉간 부팅 시험을 브링업 체크리스트에 추가).
- 전원 차단 원인(16:26~19:01): 사용자 확인 대기. 의도치 않은 차단이면 별도 조사.
