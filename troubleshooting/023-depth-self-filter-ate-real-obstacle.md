# 023 — self-filter가 로봇 앞 35cm 물체를 "자기 자신"으로 오인해서 지워버림

## 증상
troubleshooting/022(후진 사각지대) 수정 후 다시 시험했는데, 이번엔 전진하면서도 로봇이 **눈앞의
물체를 피하지 않고 그대로 비비면서 지나감**(사용자 직접 목격). depth_cloud가 local costmap에 제대로
연결돼 있었는데도(8.12) 회피를 전혀 안 함.

## 원인
라이브로 raw depth 이미지를 직접 확인해보니, 카메라는 물체를 정확히 보고 있었다 — 바닥(약 320mm)보다
훨씬 가까운 값(203~246mm)이 찍힌 픽셀들이 분명히 있었고, `base_footprint`로 변환하면 높이
4.5~8.8cm로 바닥보다 뚜렷이 솟은 진짜 물체 신호였다.

**그런데 8.12에서 넣은 self-filter(`_drop_self_points`)가 이 신호를 통째로 삭제하고 있었다.**
self-filter는 `base_footprint` 기준 x<0.16m, |y|<0.18m 사각형(로봇 풋프린트 전체) 안의 점을 전부
버리는데, 이 물체의 변환된 좌표가 x≈0.13~0.15m로 그 사각형 안에 들어갔다. 카메라가 팔 끝에서 앞으로
뻗어 아래를 보는 구조라서, 실제로는 로봇 앞 35cm인 물체도 투영 기하학상 "로봇 바로 안쪽"으로 계산된다
(카메라 위치 자체가 이미 베이스 중심보다 앞/위에 있고, 아래로 기울어 봐서 발생하는 시차).

더 근본적으로: **풋프린트(XY)로도, 높이로도 "바퀴냐 외부 물체냐"를 구분할 수 없었다.** 바퀴 반지름이
4.85cm라 바퀴 윗부분은 ~9.7cm까지 올라오는데, 이번 물체 높이(4.5~8.8cm)가 정확히 그 범위 안에 들어가서
높이 기준으로도 못 가른다. 즉 8.12의 self-filter 설계(풋프린트 사각형 하나로 전부 거르기) 자체가
"로봇 바로 앞의 낮은 물체는 못 거른다"는 구조적 결함을 안고 있었다.

## 해결
XY/높이가 아니라 **"기준 depth 이미지와의 차이"**로 자기 자신과 외부 물체를 구분하도록 바꿈
(`sparse_point_cloud.py`):
- 홈 포즈에서 팔이 안 움직이는 동안은 로봇의 바퀴/섀시가 항상 같은 픽셀에서 같은 depth로 찍힌다
  (10프레임 median으로 한 번 캡처, `config/depth_background_ref.npy`).
- 지금 들어오는 depth가 그 기준보다 **30mm 이상 더 가깝게** 찍힌 픽셀만 "새로 생긴 것 = 진짜 장애물"로
  판단해서 포인트클라우드에 포함. 기준과 같거나 더 먼 픽셀(바퀴, 평소 바닥)은 전부 제외.
- 물체가 바퀴와 XY/높이가 겹쳐도 전혀 문제없음 — 비교 기준이 "그 자리에 원래 뭐가 있었냐"이기 때문.
- TF 룩업이 필요 없어져서 `tf2_ros` 의존성도 제거함(카메라 프레임 그대로 비교, base_footprint 변환은
  필요 없음).

**주의(재현 조건)**: 이 기준 이미지는 **홈 포즈가 바뀌면 다시 캡처해야 한다** — `base.yaml`의
`arm_home_pose_rad`를 바꾸면 카메라가 보는 장면이 달라지므로 기존 기준이 무효해진다.

## 확인 (2026-10-05, 실기)
1. 물체 치운 상태로 10프레임 median 캡처 → 기준 depth 저장(유효 픽셀 91.4%, 142~431mm).
2. 물체 없이 재시작 → 발행 포인트 0개 (바퀴가 더 이상 장애물로 안 뜸, 확인).
3. 물체를 다시 로봇 앞 35cm에 둠 → 397개 포인트 발행, 높이·거리 모두 물체와 일치.
4. Nav2 local costmap에서 로봇 전방 0.1~0.5m 구간이 점유(94~100)로 찍히고, 로봇 자신의 풋프린트
   셀은 그대로 free(0) — 자기 오탐지 없이 물체만 정확히 잡힘.

**아직 안 한 것**: 이 상태로 실제 `NavigateToPose`를 다시 보내서 로봇이 이번엔 멈추거나 돌아가는지
(진짜 회피 동작) 재검증 — 지금까지는 코스트맵 반영만 확인했고 주행 재시험은 안 함.
