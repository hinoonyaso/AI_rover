# 047. Gazebo 메카넘이 옆이동을 못 함 — 롤러 마찰 방향(fdir1)의 기준 프레임이 없는 링크

- 날짜: 2026-10-19
- 상태: **해결 (host Gazebo 확인)**

## 증상
- Nav2 회피 시험(`tools/sim/avoid_trials.py`)에서 DWB가 명령한 옆이동(vy +0.14, 왼쪽)과 반대로 로봇이 오른쪽으로 22 cm 밀려 상자 앞에서 헤맸고, 회전 명령에도 중심이 이동했다. 4회 모두 시간 초과.
- `tools/sim/plant_response.py`(몸 기준 속도 응답): 왼쪽 0.10 → 오른쪽 0.02, 오른쪽 0.10 → 0.035, 대각(앞·왼쪽) → 앞 0.146 + 회전 −0.25 rad/s, 회전 −0.3 → −0.44. 전진·후진만 비율 0.84~1.0.
- Gazebo 로그: `Failed to get body node for [wheel_*_link_collision], not setting friction direction frame` (바퀴 4개).

## 원인
- 롤러 대각 마찰을 `<fdir1 gz:expressed_in="base_link">`로 줬는데, `base_link`는 fixed joint로 `base_footprint`에 합쳐져 물리 모델에 없다.
  DART가 기준 링크를 찾지 못해 프레임 지정을 무시했고, fdir1이 **바퀴 링크 좌표**에 묶여 바퀴가 구를 때마다 롤러 방향이 돌았다.
  그래서 옆이동 방향이 틀리고 대각 이동이 회전으로 샜다. (`src/jetrover_gazebo/README.md`에 "부호는 host에서 확인"이라고만 남아 있었고 확인한 적이 없었다.)

## 해결
`jetrover_sim.urdf.xacro`: `gz:expressed_in="base_footprint"`.

## 확인 (`plant_response.py`, 명령 0.10 m/s·0.30 rad/s를 6 s, 2~6 s 구간)
| 명령 | 이전 (전진 / 왼쪽 / 회전) | 이후 |
|---|---|---|
| 전진 0.10 | 0.084 | 0.089 |
| 왼쪽 0.10 | 0.022 / **−0.021** | 0.000 / **0.100** |
| 오른쪽 0.10 | −0.031 / −0.035 | 0.000 / **−0.100** |
| 대각 앞·왼쪽 0.07 | 0.146 / 0.030 / 회전 −0.248 | **0.070 / 0.070 / 0** |
| 대각 앞·오른쪽 0.07 | 0.059 / −0.008 | **0.070 / −0.070** |
| 회전 ±0.30 | 0.277 / −0.437 (중심 이동 있음) | **±0.300**, 중심 이동 0 |
`Failed to get body node` 경고도 사라졌다. 전진 0.089는 충돌 감시기 감속 구역(`FootprintSlow`) 때문으로 보인다(미확인).

## 영향
- 이 수정 전의 시뮬레이션 주행 결과(2026-10-14 이전 컨트롤러 비교 시나리오 포함)는 옆이동이 틀려 있었으므로 믿지 않는다.
- 실기 주행과 무관하다(시뮬레이션 xacro만 변경).

## 추가 (2026-10-20): sim 로봇이 실기보다 6 cm 넓었다
- 증상: 같은 footprint로 계획해도 sim에서 상자와의 간격이 실기 대비 작게 나왔다.
- 원인: sim 바퀴 충돌 형상이 구(sphere)라 바퀴가 몸 옆으로 더 튀어나왔다.
- 조치: `car_mecanum.urdf.xacro`의 `sim_mode`에서만 실기 크기 원통(반경 0.0487, 폭 0.0488, 좌 −0.0066/우 +0.0066 오프셋)으로 바꿨다. 실기 xacro 출력은 동일함을 확인했다.
