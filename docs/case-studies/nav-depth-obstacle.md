# 사례: LiDAR가 못 보는 낮은 장애물 — 충돌에서 depth costmap까지

포트폴리오용 Failure → Root Cause → Fix 정리. 근거 기록: `troubleshooting/021, 022, 023, 026, 028`.
**아직 "결과" 수치는 없다** (Nav2 baseline 시험 전). 수치 칸은 시험 후 채운다. 확인되지 않은 것을 사실처럼 쓰지 않는다.

## 1. 문제
Nav2 자율주행 중 로봇이 의자 다리와 충돌했다(2026-10-05). `collision_monitor`는 충돌 직전까지 경고를 남기지 않았다.
- 처음 의심: 왼쪽 앞바퀴 고장 → **바퀴를 띄워 단순 직진으로 격리 시험, 정상**. 메카넘의 정상적인 바퀴별 속도 차이였다.

## 2. 분석 흐름 (가설 → 시험 → 결과)
| 단계 | 가설/행동 | 결과 |
|---|---|---|
| 1 | LiDAR 스캔 평면에 얇은 다리가 안 걸린다 | costmap 소스가 `/scan` 하나뿐이라 장애물이 아예 없던 것으로 추정(021, 추정) |
| 2 | depth 포인트클라우드를 costmap 소스로 추가 | local costmap 반영 확인. 그러나 후진 recovery 중 물체를 밂 → **뒤쪽은 LiDAR(팔에 가림)·depth(전방 전용) 모두 사각**(022). 후진 금지(`min_vel_x 0`, BackUp 제거) |
| 3 | 다시 시험: 눈앞 물체를 비비며 통과 | **self-filter가 진짜 장애물을 "로봇 자신"으로 지움**(023). XY·높이로는 바퀴와 물체 구분 불가 → 기준 depth 비교 방식으로 교체 |
| 4 | 상자 앞에서 정지 | depth가 local에만 있어 **전역 경로가 상자를 통과**(026). global costmap에도 추가 |
| 5 | 상자를 침 / 요란한 회피 / 목표 직전 정지 / 직선 복귀 실패 | 앞면만 보임(extrusion 0.3 m), 감지거리 대비 속도(0.2→0.12 m/s), collision_monitor가 확대 footprint 사용, BT 웨이포인트 제거 반경 등 7개 원인을 하나씩 분리·수정(028 표) |

## 3. 배운 점
- **진단 도구를 의심해라**: 센서 데이터는 맞았고 *내가 넣은 필터*가 정답을 지우고 있었다(023).
- **한 센서로 풀면 다른 사각이 드러난다**: 전방 보강이 후방 사각을 가시화했다(022).
- **안전망(collision_monitor)이 자기 설정 때문에 정상 동작을 막을 수 있다**(확대 footprint, 028).
- 일부 해결책은 **임시 휴리스틱**임을 인정하고 한계를 문서화했다([design/depth-obstacle.md](../design/depth-obstacle.md)).
