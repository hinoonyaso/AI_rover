# 자체 펌웨어(rrc_m4) 첫 브링업 결과 (2026-10-10 ~ 11)

대상: STM32F407 RRC 보드, `firmware/rrc_m4`(RRC 모드, `MOTOR_ENABLE=ON`), 디버거는 J-Link OB 클론 + openocd.
백업(vendor, 원본 그대로): `~/firmware_source/swd_backup_20261010_130702/`(앞 82,144바이트 = 09-27에 올린 vendor 빌드, 나머지 0xFF).

## 확인된 기능
| 항목 | 결과 |
|---|---|
| 호스트 UART(USART3 1 Mbaud), 기존 `base_node`(수정 없이) | IMU 50 Hz, 배터리, `/joint_states` 5 Hz, `/cmd_vel` 주행 |
| IWDG 감독 | 모든 태스크 하트비트가 있어야 급이, 하나 멈추면 모터 PWM 0 + 리셋 |
| IMU(QMI8658) | 소프트 리셋 + 멈춘 값 감지, 냉간 부팅 확인 |
| 배터리 ADC | 부팅 첫 값 고정 버그 수정, 실제 전압 추종 |
| LED, 부저, 상태 OLED(SSD1306 128×32 I2C, IMU 버스 공유) | 정상 |
| 버튼 2개 | 4종 이벤트, K1 = id 1(PE1) |
| 모터 4개 | PWM 짝·방향·엔코더 부호 확정, 한 바퀴 3,996 카운트, PID ±0.01 rps, 바닥 주행(직진·옆이동·회전) |
| 버스 서보 | 읽기 6개, 쓰기(관절 1, 그리퍼 +눈금 = 닫힘, 홈 자세 5관절 이동), 토크 해제/걸기 동작 |
| USB 게임패드 | 버튼 14개·방향키·스틱 2개(레이아웃 실측) |
| 확장 프레임 | 0x20 상태, 0x21 바퀴 속도(엔코더 odom의 입력), 0x22 진단 명령, 0x23 원시 HID, 0x24 태스크 스택·카운터 |
| 안전 코드 | NaN/Inf 명령 폐기, 한 번에 한 출처만 제어, e-stop 유지, 엔코더 부호 가드 |

해당 없음(하드웨어 없음): PWM 서보 4채널, SBUS 수신기. 보류: 블루투스 모듈, 게임패드 직접 주행(`LOCAL_DRIVE`), micro-ROS 모드.

## 브링업에서 찾은 문제 (모두 troubleshooting에 원인·해결 기록)
| 번호 | 증상 | 원인 |
|---|---|---|
| 035 | 부팅 직후 lockup, 이어서 0.8초마다 리셋, 화면 안 바뀜 | 크리스털이 16 MHz인데 8 MHz로 가정(336 MHz 오버클럭), LCD 태스크 스택 넘침, 화면이 SPI LCD가 아니라 I2C OLED |
| 036 | 오른쪽 앞바퀴가 시험 후 최대 속도로 계속 회전 | PWM 핀 짝 추정 반대 + 폭주 감시가 목표 0에서 못 보고 e-stop이 PID를 안 막음 |
| 037 | 전원을 껐다 켠 뒤 IMU 값이 멈춤 | 소프트 리셋 누락(vendor가 초기화해 둔 칩에서만 동작) |
| 038 | 배터리 값이 부팅 첫 값으로 고정 | ADC DMA 재시작 거부 |
| 039 | 게임패드가 중립인데 버튼 눌림으로 보고 | HID 리포트 ID 때문에 모든 필드가 한 칸씩 밀림 |

공통 교훈: 추정으로 둔 하드웨어 상수(핀, 레이아웃, 크리스털)는 브링업 순서(통신 → 센서 → 출력 → 모터)대로 하나씩 실측으로 확정했고,
"처음 값만 계속 나오는" 종류의 버그(037, 038)는 값이 실제로 변하는지 확인해야 보였다. 안전장치는 목표가 있을 때만이 아니라
출력과 측정이 모순될 때를 봐야 했다(036).

## 확인 못 한 것 / 남은 것
- 호스트 강제 종료·명령 timeout 실기 시험(E3), 저전압 차단 실기, 그리퍼 파지 값
- 게임패드 L1 마스크(문서 0x0400은 오타로 보고 0x4000), K1 = id 1 규약은 vendor 펌웨어·호스트 SDK와 대조 안 함
- 장시간 안정성: `tools/stm32_diagnostics/soak_log.py`(SWD, 1분 간격)로 기록 시작(2026-10-11 01:10), 결과는 `Log/soak_20261011.csv`
- 토크가 풀린 동안 서보 위치 읽기가 갱신되지 않음(서보 특성으로 추정)
