# RAG 문단 순위 및 생성 답변 추가 평가 (2026-11-19)

## 변경
기존 점수는 문서 경로의 반복 단어가 모든 청크에 반영되고 문서당 최고 점수 한 청크만 선택하므로, 문서의 다른 위치에 있는 정답 근거가 밀릴 수 있었다. 기존 벡터·문자 일치 점수와 후보 허용 조건을 유지하고, 질문에 포함된 글자 2-gram이 여러 청크 중 얼마나 희귀한지 문단 본문만으로 계산해 순위 점수에 추가했다. 색인 형식·모델은 바꾸지 않았다. 빈도 가중치는 검색 정확성을 보장하지 않으며 점수는 정답 확률이 아니다. 영어 `LiDAR`가 실시간 질문 판별 대상에서 누락된 것도 추가했다.

## 1차 평가 방법과 결과
모두 동일하게 복원한 195청크 색인과 모델을 사용했다. 상위 3개 결과 중 지정된 출처와 정답 문자열을 포함한 문단을 채점한다. 문자열 기준이므로 동의어는 불일치일 수 있다. 모든 질문 작성자는 프로젝트를 알고 있어 외부 블라인드 평가가 아니다. 튜닝에 사용한 기존 17문항과 개발 과정에서 확인한 새 14문항은 일반화 성능으로 취급하지 않는다. 가중치 확정 뒤 별도 최종 14문항을 만들어 같은 코드·색인에서 변경 전후 비교했다.

| 사례 | 변경 전 | 변경 후 |
|---|---:|---:|
| 조정에 사용한 질문: 문단 근거 | 4/12 | 5/12 |
| 조정에 사용한 질문: 무관·실시간 유보 | 5/5 | 5/5 |
| 개발 중 확인한 질문: 문단 근거 | 8/10 | 9/10 |
| 개발 중 확인한 질문: 무관·실시간 유보 | 3/4 | 4/4 |
| 최종 별도 질문: 문단 근거 | 8/10 | 8/10 |
| 최종 별도 질문: 무관·실시간 유보 | 3/4 | 4/4 |
| 기존 15문단 평가(대안 문자열 중 하나) | 12/15 | 12/15 |

최종 별도 질문에서 변경된 한 건은 현재 LiDAR 수신 주파수 질의를 문서 검색 대신 유보한 것이다. 정답 근거 8건은 생성 모델에 실제 전달하는 각 700자 안에도 들어갔다. 이 사례에서는 정답 문단 개선이 없었고, 기존 조정 질문에서도 7/12건이 여전히 미일치다. 최종 질문 14건의 1회 측정에서 검색 중앙값 53→76ms, p95 68→89ms였다. 첫 로딩 제외, 캐시·부하·표본 수에 따라 달라지는 참고 수치다. 최종 질문과 세부 출처·오프셋은 `knowledge_final_holdout_20261119.json` 및 `rerank-holdout-{before,after}-20261119.json`에 기록했다.

## 추가 문단 적용과 2차 평가

한 문서에서 정답이 다른 위치에 있는 경우를 위해, 선택된 문단과 960자 이상 떨어져 있고 점수 차가 0.35 이하인 같은 문서·동일 SHA-256의 관련 문단을 최대 한 개 더 제공한다. 주 문맥은 최대 1,050자, 추가 문단은 최대 400자를 생성 모델에도 함께 전송한다. 외부 API를 선택하면 이 추가 문단도 전송할 수 있으므로 화면의 확인 문구에 명시했다. 문서가 같아도 색인 버전이 다른 청크는 합치지 않으며 회귀 테스트로 확인했다.

1차 조정에 사용된 12개 질문은 **4/12 → 8/12**, 무관 유보 5/5였다. 1차 최종 14개 질문은 8/10·4/4를 유지했고, 기존 문단 평가는 12/15와 7/8을 유지했다. 추가 적용 이후 작성해 별도로 실행한 12개 질문은 변경 전 6/8·3/4에서 변경 후 **6/8·4/4**였다. 해당 별도 질문의 정답 근거가 검색된 6건 모두 모델에 전송하는 문맥에도 포함됐다. 새 질문 역시 프로젝트를 아는 작성자가 만들었으므로 외부 블라인드 성능을 뜻하지 않는다. 추가 문단은 같은 문서의 별도 위치이며 정답임을 보장하지 않는다. 상세: `rerank-second-holdout-{before,after}-20261119.json`, `rerank-tuning-final-20261119.json`.

## 생성 답변 추가 평가
2차 추가 문단 변경 전, 서로 다른 두 질문에 동일한 상위 3개 검색 결과를 주고 각 모델을 1회 실행했다. Qwen은 CPU 2스레드, 최대 256토큰, EXAONE은 reasoning low, 최대 1024토큰(추론 포함)이며 설정·시점이 달라 속도 우열을 일반화할 수 없다. 질문과 문단은 EXAONE 외부 API에 전송됐다.

| 질문 | 로컬 Qwen | EXAONE |
|---|---|---|
| CH340에 필요한 커널 모듈 | 107.69초. `ch341`을 언급했지만 `cp210x`, `ftdi_sio`를 대안처럼 잘못 추가, 출력 미완결 | 16.99초. `ch341` 및 `modinfo ch341`을 근거에 맞게 제시 |
| 가속도 6자세와 교차축 | 101.67초. 미측정이라는 결론은 맞았으나 [3]을 관련 근거처럼 잘못 인용 | 19.16초. 축별 오프셋·배율 후보이며 교차축 보정이 아니라는 내용을 인용 |

실시간 LiDAR·무관 일출 질문은 검색 결과가 없어 두 모델 모두 호출하지 않았다. 이 4개 질문은 생성 평가를 위해 선택했으며 독립적인 전체 품질 추정이 아니다. 기본 답변은 원문 근거이고 생성 결과는 사용자 확인이 필요하다. 세부 응답은 `rerank-generation-comparison-20261119.json`.

## 실제 센서 동시 부하
대시보드·IMU·LiDAR·컬러 카메라·깊이 장애물 데이터를 켠 상태에서 로컬 모델 답변 1회에 대해 94.6초간 센서 스냅샷을 45회 측정했다. 모니터 스냅샷 오류·8초 이상 지연 0회, 네 스트림의 10초 이상 미수신 0회. 최고 CPU 98.3%, 최소 여유 메모리 2.16GiB, 최대 스왑 사용 0.91GiB였다. 생성 중 별도 60초의 2초 간격 30개 표본에서 IMU 중앙값 49.5Hz, LiDAR 13.9Hz, 카메라 23.35Hz, 깊이 장애물 6.9Hz였다. `rerank-generation-load-20261119.json`은 생성 중 스냅샷 표본이다. 이는 정지 상태의 단일 생성 시험이며 자율주행 안전이나 장시간 운영을 보장하지 않는다.

생성 종료 후 동일한 60초·2초 간격 30개 표본의 중앙값은 IMU 49.5Hz, LiDAR 13.9Hz, 카메라 29.1Hz, 깊이 장애물 7.4Hz였다. 따라서 이 단일 비교에서 카메라 수신 주기가 생성 중 낮았지만 원인과 반복 재현성은 추가 검증이 필요하다. 종료 후 표본은 `rerank-sensor-idle-20261119.json`.

## 추가 문단 적용 후 긴 문맥 실제 생성

CH340 설치 후 RPLIDAR 장치 번호 질문에서 검색 결과의 해당 근거가 기존 700자 제한 밖에 있어 보이지 않던 사례를 확인했다. 주 문맥 최대 1,050자와 추가 문단 최대 400자를 허용한 뒤 EXAONE과 로컬 모델에 각각 실제 요청했다. 모델당 세 결과의 문맥 길이는 1,040·1,456·1,456자였다. EXAONE은 8.1초에 `ttyUSB1`을 기록에 맞게 답했고, 로컬 모델도 번호는 맞혔으나 GET_INFO가 장치 번호를 반환한다는 식의 근거 없는 설명을 덧붙였다(145.3초, 테스트·빌드 병행). 로컬 문맥 길이 제한으로 인한 실행 오류는 없었지만 정확도와 모든 긴 입력의 성공을 보장하지 않는다. 원문 출처를 확인해야 한다.

## 평가셋 재사용 주의 (2026-11-22 검토 추가)

이 문서의 "최종 별도 질문"과 "별도 질문"은 변경 후 결과를 본 뒤 다시 조정하는 과정에 차례로 쓰였다. 한 번 결과를 보고 조정에 반영한 질문 묶음은 더 이상 홀드아웃이 아니다(평가셋 오염). 따라서 위 수치는 **개발 중 회귀 확인용**이고, 일반화 성능 주장이나 포트폴리오의 정확도 수치로 쓰지 않는다. 일반화 성능은 프로젝트를 모르는 작성자가 만든 새 질문으로 **조정 없이 1회** 측정해야 한다(체크리스트 32 RAG 항목의 "외부 블라인드 평가").
