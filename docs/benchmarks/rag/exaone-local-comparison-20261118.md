# EXAONE과 로컬 모델 RAG 비교 — 2026-11-18

## 방법
기존 대시보드 검색 API에서 질문별 상위 3개 문단을 한 번 얻어 동일한 문단과 동일한 시스템 지시문을 두 모델에 전달했다. 문서 내용과 질문은 EXAONE 외부 API로 전송되었다. 질문은 이전 시험에서 오류가 확인된 카메라·자이로 2건이다. 로컬은 Jetson CPU의 Qwen3 1.7B Q4, 2스레드, 최대 출력 256 토큰, temperature 0.1이다. EXAONE은 `k-exaone_v2.5`, reasoning_effort low, 최대 1024 토큰(추론 포함), temperature 1.0/top_p 0.95다. 모델별 설정과 실행 환경이 다르며 각 성공 응답은 1회여서 일반적인 품질·속도 비교는 아니다. 응답 지연은 모델 요청 시작부터 완료까지이며 문서 검색은 제외했다.

## 결과
| 질문 | 로컬 모델 | EXAONE |
|---|---|---|
| DaBai 카메라 인식 오류 | 79.54초. udev 규칙이 해당 문제 해결에 필요하다고 설명해, udev 문제는 별개였다는 기록과 충돌 | 최초 429(서비스 동시 요청 혼잡); 같은 문단으로 재시도 성공 59.40초. USB 시리얼 부재, udev 문제와의 구분, SDK v1 우회에 대해 제공된 문단에 맞게 답변 |
| 기존 자이로 bias 반영 | 76.96초. 정지 상태에서 보정이 실행되지 않는다는 근거 없는 설명을 포함 | 88.82초. 제공된 상위 3개 문단에 기존 bias와 잔차 계산 규칙이 없음을 지적하고 답변을 유보 |

카메라 재시도와 로컬 자이로 실행은 시간이 겹쳐 동일한 부하 조건이 아니다. 생성형 답변의 근거 일치 여부는 문단과 수동 대조했다. 자이로의 실제 계산 규칙은 `prd/dashboard-sensor-calibration.md`에 있으나 검색 결과 상위 3개 문단에는 포함되지 않았다. 문서 검색 성능 개선이 여전히 필요하다.

EXAONE 2개 성공 요청의 사용량은 각각 총 908·1290 토큰이고 응답의 reasoning_tokens는 각각 209·474였다. 429 조사 시 계정 한도 헤더에는 일일 잔여 호출이 남아 있었고 응답 본문은 서비스 동시 요청 혼잡을 나타냈다. 이 수치로 비용이나 이후 가용성을 확정할 수 없다.

재현 코드: `tools/ops/evaluation/compare_exaone_local.py`. 키는 `tools/ops/.env`, 대시보드 로그인 암호는 실행 시 환경 변수로 읽는다. 응답과 출처 오프셋은 `exaone-local-comparison-20261118.json`에 기록했다. EXAONE은 평가용으로 직접 호출했으며 대시보드 기능에는 아직 연결하지 않았다. 2개 질문, 모델별 1회 성공 결과로 전체 정확도와 속도 우열을 확정하지 않는다.
