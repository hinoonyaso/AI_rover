# 접촉 파지 L2 실기 시험 2: 취소·배타 제어·이상 (T6, 2026-10-15)

PRD `prd/arm-control-path.md` R4·R5·R6, TEST_PLAN T6 L2. 앞선 파지 8회는 `arm_grasp_l2_20261014.md`.
도구: `tools/stm32_diagnostics/grasp_l2_faults.py`(시나리오 5개), 원자료 `docs/benchmarks/arm_grasp_l2_faults_20261015/*.json`.
조건: 자체 펌웨어 rrc_m4, 배터리 12.53 V, 팔은 홈 자세 그대로(**그리퍼만 움직임**), 3 cm 큐브를 사용자가 손으로 놓음,
프로파일 `cube3cm`(임시값: 창 [505, 545], 조임 +16, 유지 ±3, 제한 30 s, 온도 80 ℃). 세션 1은 `robot.launch.py arm_command_enabled:=true`,
세션 2·3은 base_node를 직접 띄워 파라미터만 바꿈(`-p grasp_timeout_s:=6.0` / `-p grasp_temp_limit_c:=30.0`).
도구는 실기 전에 L1 가짜 장치(pty)로 다섯 시나리오 모두 통과시킨 뒤 썼다. **실제 하드웨어 증거.**

## 무효로 뺀 회차 (시험 절차 문제, 파지 로직 문제 아님)
- 조이는 중 취소 1차 2회: 사용자가 큐브를 넣지 않음(직전 안내가 온도 이야기여서 온도 확인으로 이해) → 끝점 근처(615 / 683)까지 닫혀 Squeeze에 못 감.
- 조이는 중 취소 2차의 2회차: Squeeze 취소는 그리퍼를 **접촉 위치에 둔 채** 끝나는데(정책대로), 다음 회차 전에 열지 않아 시작 위치 526 → 파지가 곧바로 끝남
  (그리퍼 움직임 없음, 시작 위치 ≤ 450 조건). 도구가 결과를 늦게 요청해 이유를 못 받음(status 0) → 도구 수정: 수락 직후 결과 요청, 회차 전 자동 열기.
- HOLDING 거부 1차: "대조 중엔 큐브를 넣지 말라"는 안내 뒤 넣을 시점을 알 수 없어 큐브 미배치 → `NoContact`. 대조는 큐브가 있어도 상관없어 처음부터 넣게 바꿈.

## 실기에서 하지 않은 것 (Not Run — L1 가짜 장치 증거만)
- **HOLDING 중 이상(고온·통신 두절)**: 실제로 안전하게 일으킬 방법이 없음. L1에서 "공중 고온에서 명령 0, `needs_user`" 확인됨.
- **HOLDING + 지면 근처 → 열기 경로**: 자세 기반 들어 올림 판정(`set_pose_lifted`)을 아직 아무도 호출하지 않아 들어 올림이 항상 "모름" →
  모르면 들어 올린 것으로 보므로 실기에서는 HOLDING 이상 때 **항상 열지 않고 사용자 호출**(안전한 기본값). 지면 열기 경로는 실기에서 일어날 수 없다.
- HOLDING 중에는 Action goal이 이미 끝나 있어 "HOLDING 중 취소"는 Action으로 보낼 수 없다(설계대로; 해제는 `arm/release`).

## 덤으로 관찰한 것
- 시작 직후 `/joint_states`의 joint3이 2.161 rad(펄스 약 −16, 범위 밖)로 10 s 넘게 같은 값 → 나중에 1.667(홈). joint3에 명령은 없었다
  (`on_arm_command`는 이름 있는 관절만 보냄 — 그리퍼만 보냈음). 서보 3의 실패 응답이 다른 서보보다 많았다(8 vs 2).
  잘못 읽힌 값이 실패 응답 동안 갱신되지 않은 것으로 추정. **base_node는 0~1000 밖 펄스도 그대로 받는다** → troubleshooting/041.
- 그리퍼 온도는 36~54 ℃ 사이(한 번 54 ℃ 다음 회차 46 ℃ — 측정 튐 가능), 80 ℃ 기준 아래.
