# 팔 홈(주행) 자세 재설계 실험 — 2026-10-09

ROADMAP 1-2 / checklist 8.13.5. 신뢰 수준: **확정**(실기 측정).
도구: `tools/perception/home_pose_eval.py`(지표), `arm_set_joint.py`(관절 이동), `capture_depth_reference.py`(기준 depth).
원자료: [home_pose_20261009.csv](home_pose_20261009.csv), 그림: `home_pose_20261009_j4_*.png`.

## 목적
depth 카메라가 팔 끝(link4)에 있어 팔 홈 자세가 곧 장애물 감지 시야다. 기존 홈(2026-10-05)은 앞 0.21~0.62 m만 보여
0.12 m/s에서 반응 여유가 약 3.6 s였다. 목표: 가까운 끝 ≤ 0.25 m 유지, 먼 끝 ≥ 0.8 m, LiDAR 가림 악화 없음.

## 방법
- 조건: 배터리 11.7 V, 로봇은 지도 (1.04, 0.35)에서 빈 직선(약 1.8 m)을 향해 정지, Nav2/카메라(colorizer 끔) 가동.
- 손목(joint4)만 바꾸고 나머지 관절은 그대로. 각 자세에서 depth 15프레임 중앙값을 TF(실제 관절값 기준)로 base_footprint에 투영.
- 지표 정의는 `tools/perception/README.md`. 바닥 = z ±3 cm, 가까운/먼 끝 = 바닥 점 전방거리 5/95 백분위.
- 사전 계산(높이 0.33 m, 세로 시야 ±26.4°): 먼 끝 0.9 m를 보려면 숙임을 61° → 약 50°로 줄이면 됨(손목 약 0.2 rad).

## 결정
**joint4 = 1.45** (사용자 선택, 2026-10-09): 먼 끝 목표(≥ 0.8 m) 충족, 가까운 끝 0.26 m로 목표(0.25)에 근접, 사각지대 최소(8 cm).
- `base.yaml` `arm_home_pose_rad`: `[0.0042, -0.6618, 1.6629, 1.6043, 0.0168, -0.0209]` → `[..., 1.45, ...]`(joint4만 변경).
- 기준 depth 재촬영: 30프레임, 유효 91.9%, 노이즈 중앙값 0.6 mm / p95 2.0 mm(margin 60 mm 대비 충분).
  이전 기준은 `src/jetrover_perception/config/depth_background_ref.20261009_185901.npy`로 자동 백업.
- 적용 확인: 재기동 시 팔이 새 홈으로 이동, 홈 자세 게이트 열림(최대 오차 joint3 0.029 rad), **빈 바닥 거짓 점 31프레임 모두 0**.

## 시험 중 발견한 문제
1. **팔/카메라 TF가 끊김**: 팔을 두 번 움직인 뒤 `robot_state_publisher`의 관절 TF(`base_link→link1…`)와 카메라 드라이버의
   color 프레임 TF가 나오지 않음(두 노드는 살아 있고 `/joint_states` 4 Hz 정상, 연결도 정상). base/카메라 launch 재시작으로 복구,
   이후 재발 없음. **원인 미확정** — 재발하면 조사(troubleshooting 기록).
2. **`arm_set_joint.py` 명령 유실**: 퍼블리셔 생성 직후 한 번만 보내 DDS 연결 전에 사라짐(측정 1회가 홈 자세로 잘못 기록 →
   CSV에서 `home_recheck_after_restart`로 이름 정정). 구독 연결을 기다린 뒤 보내도록 수정.
3. 서보 유격: 같은 목표 1.45라도 위에서 내려오면 1.458~1.474, 아래에서 올라가면 1.445로 멈춤(±0.015 rad). 게이트 허용 0.08 rad 안.
