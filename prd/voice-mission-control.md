# PRD: 음성 → 실제 임무 연결 (초안)

작성: 2026-11-22. 상태: **초안, 사용자 승인 전**. 구현·체크리스트 분해는 승인 후 한다. 지금 음성은 상태 조회·문서 질문·모의 임무(확인 필요)까지만 한다(`tools/ops/backend/robot_voice.py`).

## 목표
"Hello Hiwonder, 경광등 점검해"처럼 말로 **정해진 임무**를 요청하고 취소할 수 있게 한다. 순서는 Gazebo 임무 → 실제 로봇 임무다. 음성은 임무를 **요청**하는 입구일 뿐이고, 실행 판단과 안전은 기존 임무 관리자·Nav2·collision_monitor·물리 전원 스위치가 맡는다.

## 범위
1. **V1 Gazebo 임무 음성 요청**: 기존 `gazebo` 모드 임무(경광등 점검)를 음성으로 생성·시작·취소. 실제 로봇 무관.
2. **V2 실제 로봇 임무 음성 요청**: 허용 목록의 실기 임무만. 아래 안전 게이트를 모두 통과해야 확인 단계로 간다.
3. **음성 취소**: 진행 중 임무 취소 요청(Nav2 goal 취소 + 0 속도). 물리 비상정지를 대신하지 않는다.
4. **감사 기록**: 깨운 시각·방향, 전사 문장, 해석 결과, 확인 방법(음성/버튼), 확인한 계정을 임무 이벤트에 저장.

## 비범위
- 자유 문장을 LLM이 바로 로봇 명령으로 바꾸는 것. (나중에 쓰더라도 정해진 JSON 형식 출력 → 서버 검증 → 사람 확인 순서. LLM 출력은 실행 권한이 없다.)
- 음성으로 팔 직접 조작, 속도·거리 지정 주행("앞으로 1미터"), 원격 수동 조종.
- 깨우기 방향으로 회전·접근(방향 오차 약 15°, `prd/audio-doa.md`).
- YOLO/물체 집기 임무(로드맵상 인식 단계 이후).

## 안전 게이트 (V2, 모두 충족해야 확인 단계로 진행)
| 게이트 | 내용 |
|---|---|
| 음성 실기 허용(Arm) | 운영자가 대시보드에서 켜는 시간 제한 스위치(예: 10분). 꺼져 있으면 실기 임무 음성 요청은 거부 |
| 로봇 준비 | 배터리 기준 이상, IMU·LiDAR·깊이 장애물 점 수신(대시보드 기준과 동일), 팔 홈 자세, collision_monitor active, 진행 중 임무 없음 |
| 미해결 안전 이슈 | 낮은 장애물 측면 접촉(`troubleshooting/061`)처럼 실기 주행을 중단시킨 이슈가 열려 있으면 해당 임무 유형 차단 |
| 확인 | 해석 결과를 화면과 스피커로 되읽고 30초 안에 확인. **실기는 대시보드 버튼 확인만** 허용할지 음성 확인도 허용할지 결정 필요(아래 질문) |
| 취소 | 항상 허용, 로컬 처리(클라우드·STT 서버 장애와 무관하게 대시보드 버튼은 동작) |

## 명령 해석
- 지금처럼 규칙 기반 의도 + 허용 목록. 슬롯은 임무 종류(허용 목록)와 장소(고정 지점 목록; 의미 지도 22장은 미구현)만.
- 모호하거나 목록에 없는 장소·임무는 되묻거나 거부. 실제/모의/Gazebo 모드는 말로 바꾸지 않고, 요청 시 현재 선택된 모드를 되읽는다.

## 제약
- AGENTS.md 개발 순서상 Voice는 MoveIt2 이후, Mission BT 전이다. 이 PRD는 기존 모의/Gazebo 임무 관리자 위에서 동작하며 BehaviorTree.CPP 도입(17장) 전 단계다.
- 실기 L4/L5는 사용자 입회·전원 스위치 곁·별도 승인. 2026-11-22 기준 061 미해결로 실기 주행 임무는 V2 착수 전에 해결이 필요하다.
- STT 서버 장애 시 CPU CLI로 대체되며 지연이 늘 수 있다. 음성 경로 지연이 안전 판단에 쓰이지 않게 한다.

## 완료 기준
- V1: Gazebo 임무를 음성으로 생성·시작·취소, 확인 전 미실행, 모호 요청 거부, 이벤트에 감사 기록. 격리 시험 + Gazebo 실행 3회.
- V2: 게이트 하나라도 미충족이면 실행 0회(각 게이트별 거부 시험), 확인 후 실행, 음성·버튼 취소가 1초 안에 Nav2 취소 요청을 보냄. 실기는 별도 시험 계획(`-test-plan.md`)과 승인 후.

## 결정이 필요한 질문
1. 실제 로봇 첫 음성 임무는 무엇인가? (예: 정해진 지점으로 이동 후 경광등/설비 점검, 출발점 복귀)
2. 실기 임무의 최종 확인을 **대시보드 버튼만** 허용할까, "Hello Hiwonder, 확인" 음성도 허용할까?
3. 음성 실기 허용(Arm) 스위치의 유효 시간과, 운영자 외에 켤 수 있는 사람이 있는가?
4. 음성 "멈춰/취소"는 Nav2 취소 + 0 속도까지만 할까, collision_monitor 수동 정지 상태(재개 시 확인 필요)로 둘까?
