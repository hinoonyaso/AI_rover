# 설비 점검·웹 관제·음성·RAG 우선 작업 계획

작성: 2026-11-19. 요청: 경광등 점검, 웹 관제, 음성·LLM, RAG를 다른 로봇 기능보다 먼저 진행한다. 이 문서는 계획이며 완료 표시가 아니다.

## 목표와 범위

대시보드에서 점검 영상과 근거, 결과와 이력을 이해할 수 있고, 음성으로 문의·모의 임무를 요청하고 취소할 수 있게 한다. 프로젝트 문서는 출처가 있는 검색으로 제공한다. 이미 구현된 기능은 재구현하지 않고 현재 동작과 테스트를 먼저 확인한다.

실물 경광등 제작은 전제하지 않는다. 실제 로봇 주행·팔 구동이나 실제 설비 판정은 별도 단계다. 최근 5cm 장애물 접촉 및 정밀 접근 충돌 검사가 미해결이므로, 모의/Gazebo 검증을 실제 로봇 구동 승인이나 안전성 증명으로 간주하지 않는다. 입력 영상이 없으면 합성·기존 가상 영상까지 수행하고 실물 영상 정확도는 미검증으로 남긴다.

## 순서와 의존관계

1. 공통 기준선: 기존 PRD·테스트·실행 경로 및 서비스/권한을 정리하고 모의 환경에서 재현한다.
2. 설비 점검: 영상 입력과 근거·실패 사유를 정리하고 점검→저장→보고 경로를 검증한다.
3. 웹 관제: 실제 센서 표시와 임무·점검 이력, 오류/복구 및 LAN 접근을 검증하고 보완한다.
4. RAG·Vector DB: 검색과 근거 답변 및 운영 복구를 먼저 개선하고, 로컬과 EXAONE 생성 답변은 별도 평가한다.
5. 음성·LLM: 상시 청취와 명령 해석을 구현하고 먼저 모의 임무·질의와 연결한다. 2~4의 안정된 API를 재사용한다.
6. 네 기능을 모의/Gazebo에서 통합 검증한다. 실제 로봇 명령 연결은 주행 안전과 별도의 권한·중단 설계가 충족된 뒤 진행한다.

단계별 완료 여부는 실제 실행 증거를 남기고, 부족한 외부 입력이나 하드웨어가 필요한 검증은 분리해 기록한다. 과거 Gazebo 주행 시간 초과는 현재 우선 조사 대상으로 두지 않으며 새로 재현될 때만 다룬다.

## 1. 설비 점검·경광등

**현재:** 가상 경광등 생성·관측·Gazebo 임무 및 결과 저장이 있다. 가상 시험판에 맞춘 색상 탐색은 실제 환경에 일반화되지 않았으며, 영상 누락이나 시야 이탈이면 판정을 유보한다.

**작업**

1. 기존 관측기와 임무·결과 스키마를 점검하고 합성·Gazebo 영상의 기준 사례와 실패 사례를 보존한다.
2. 비디오 파일/카메라의 동일한 관측 인터페이스를 구성하고 색상별 on/off/판정 불가, 표본 수·시각·사유·출처와 결과 근거 이미지를 저장한다. 기존 이력과 API 호환성을 유지한다.
3. 조명·노출·배경·부분 가림·색상 반전·영상 중단을 포함하는 평가 데이터와 기대값을 분리한다. 가상 데이터는 가상으로 표기한다.
4. 점검 위치, 관측 자세와 결과 보고를 모의/Gazebo 임무에 연결하고, 실패·취소·재시작 후 이력 복구를 확인한다.
5. 실물 경광등 없이 사용자가 준비한 대체 실제 영상이 생기면 동일 평가를 수행한다. 별도 실물 설비·주행 연동은 이후 단계다.

**완료 기준:** 미수신·표본 부족·가림에서 임의로 정상 판정하지 않으며 관측 근거와 실패 이유가 화면과 이력에 보인다. 가상 및 제공된 실제 영상의 성능은 각각 독립 평가하고 혼합해 성공률을 주장하지 않는다.

## 2. 웹 관제

**현재:** 로그인·권한, HTTPS LAN 접근, 센서 상태와 카메라, DB 탐색, 보정 및 모의/Gazebo 임무가 있다. 실제 로봇의 모터·팔 제어 및 물리 비상정지는 제공하지 않는다.

**작업**

1. 실제 센서의 ROS 토픽·수신 시간과 대시보드 표시를 구동 없이 대조하고, 카메라 영상 수신과 장애물용 depth cloud 수신을 구분한다. 팔 홈 자세 이탈, 데이터 만료·복구도 확인한다.
2. 서비스 중단·재시작, DB 중단·복구, 임무 중 서버 재시작, 권한·세션 오류를 격리 환경에서 시험하고 문제를 수정한다. 화면과 API에 연결 실패 및 복구 상태를 표시한다.
3. 다른 물리 PC에서 인증서 지문 확인 후 HTTPS 접속·로그인·조회/운영자 권한을 확인한다. 기존 인증정보·네트워크 설정은 임의로 변경하지 않는다.
4. 센서·카메라·DB·검색·대시보드의 동시 운영 및 재부팅 복구 시험을 준비한다. 시간·부하 기준을 사전에 기록하고 서비스 복구 및 로그 보존을 확인한다.
5. 실제 임무 제어와 비상 중단은 별도의 안전·권한 설계와 검증 이후 연결한다. 웹 버튼이 물리 비상정지를 대체한다고 표현하지 않는다.

**완료 기준:** 센서별 값/수신 시각이 원본과 일치하고 이탈·장애·복구가 사용자에게 구분된다. 권한·복구 시험과 원격 PC 접속 결과를 실제 시험 조건과 함께 기록한다.

## 3. RAG·Vector DB

**현재:** 허용 문서 기반 Qdrant 로컬 색인, 혼합 검색, 원문 근거 표시 및 탐색이 있다. 기존 소규모 평가에서 생성형 답변 2건에 오류가 있었으며, EXAONE 비교는 했지만 대시보드 생성 경로에 연결돼 있지 않다.

**작업**

1. 질문·기대 근거·무관/근거 없음·실시간 상태 질의를 포함한 독립 평가셋과 채점 기준을 만든다. 기존 튜닝용 평가셋과 분리한다.
2. 실패 원인을 수집·청크·순위·근거 선택·생성 단계별로 분석하고, 필요할 때만 검색/문맥/거부 로직을 개선한다. 출처와 색인 버전을 유지하고 재색인 실패 시 기존 세대를 보존한다.
3. Qdrant 색인과 메타데이터의 백업·별도 디렉터리 복원, 손상·잠금·모델 부재를 검증한다. 운영 DB를 임의 삭제하거나 덮어쓰지 않는다.
4. 로컬 모델과 EXAONE을 동일 질의·근거·채점 기준으로 비교해 정확성·근거 준수·거부·응답시간과 비용/외부 전송 조건을 기록한다. 실사용 선택은 평가 결과에 따른다.
5. EXAONE 연결이 필요하다고 판단되면 설정으로 명시 선택하는 경로를 추가하고 기본 근거 답변은 유지한다. 키는 Git 제외 환경변수로 관리하고 외부 전송 내용은 화면에서 명확히 표시한다.
6. 센서·대시보드와 검색/생성을 동시 실행하며 수신 지연, CPU/RAM/스왑, 요청 실패와 복구를 측정한다.

**완료 기준:** 독립 평가셋에서 변경 전후를 같은 채점 기준으로 비교하고 근거 부족은 명시한다. 백업 복원과 장애 복구를 시험하며 로컬/EXAONE의 장단점과 실제 선택 상태를 구분해 기록한다. 검색 결과는 안전 판단이나 로봇 동작에 직접 사용하지 않는다.

## 4. 음성·LLM

**현재:** 단발 녹음→Whisper STT→로컬/선택형 클라우드 LLM→Piper TTS 시험 경로가 있다. 상시 청취, VAD, 음성 임무 전송은 미구현이다.

**작업**

1. 기존 단발 경로와 마이크·스피커 장치 선택, 중복 점유·오류 복구를 먼저 확인한다.
2. 상시 입력에 VAD·발화 종료·녹음 길이 제한을 추가한다. 깨우기는 장치·오탐률·한국어 사용성을 비교해 적합한 방식으로 선택하고, 화면에 듣기/처리/응답 상태와 마이크 끄기를 제공한다.
3. STT 결과를 제한된 구조화 명령(상태 조회, 문서 질의, 모의 임무 시작·취소)으로 변환한다. 모호하거나 신뢰할 수 없는 요청은 되묻고, 발화와 해석된 명령을 확인할 수 있게 한다.
4. 문서 질문은 RAG와, 실시간 상태 질문은 기존 상태 API와 연결한다. 모의/Gazebo 임무 API를 사용해 요청·취소와 실패 응답을 연동한다.
5. 조용한 환경·일상 소음·TTS 재유입·취소·마이크 단절·STT/LLM 장애를 시험하고 지연·오인식·오작동을 기록한다. 외부 LLM 사용은 선택 사항이며 음성/문서 외부 전송은 명시적으로 표시한다.
6. 실제 로봇 명령 연동은 안전 게이트와 별도 승인·실기 검증 이후에만 진행한다.

**완료 기준:** 음성 입력을 끄고 켤 수 있고, 무음·오인식·모호한 요청이나 서비스 실패에서 임의 임무를 실행하지 않는다. 모의 임무의 요청·취소와 상태·문서 질의의 응답을 실제 마이크/스피커 및 격리 자동 테스트로 확인한다.

## 기록 및 검증

구체적인 사례와 통과 조건은 `prd/inspection-web-voice-rag-test-plan.md`를 따른다. 기존 문서와 충돌하면 최신 코드·실행 결과를 확인하고, 완료·부분 완료·미검증을 구분한다. 체크리스트는 `checklist/PROJECT_CHECKLIST.md`의 우선 작업 섹션에서 관리한다.

### 음성 구현 결정 (2026-11-19)
브라우저가 사용자가 활성화한 마이크의 PCM을 로컬 VAD로 분절해 HTTPS로 전송하고 Jetson의 기존 Whisper로 한국어 전사한다. 별도 깨우기 모델 대신 각 발화 앞의 제한된 호출어를 전사 후 검사하는 시제품이다. 오탐·지연과 마이크 품질은 별도 실측한다. VAD는 고정 RMS 기반이므로 모든 소음 환경에서 성능을 보장하지 않는다. 녹음·전사·응답 중 중복 요청을 막고 끄기, 실패·권한 거절·장치 해제 상태를 표시한다. 브라우저 음성 합성 중 입력을 무시해 재유입을 줄이지만 완전한 에코 제거는 아니다.

전사 텍스트는 허용된 고정 규칙으로만 상태 조회·지식 근거 질의·모의 점검 생성/실행·모의 임무 취소를 분류한다. 임무 쓰기는 사용자가 인식·해석을 보고 화면 또는 호출어를 포함한 확인 발화로 승인한 후 기존 인증 API를 호출한다. 취소는 활성 모의 임무 한 건만 확인할 수 있을 때만 허용한다. 모호·실기·Gazebo 주행/조작은 거부한다. LLM 출력과 RAG 문구를 임무 명령으로 실행하지 않으며 실시간 값은 상태 API에서 가져온다. 음성 데이터는 전사 시 임시 저장하고 자동 정리하며 기본적으로 외부 서비스에 전송하지 않는다. 로그인한 운영자만 전사·임무 쓰기를 사용한다.
