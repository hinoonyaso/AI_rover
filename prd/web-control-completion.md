# 웹 관제 보완 범위

2026-11-17 사용자가 로봇 실동작을 제외한 기존 웹 관제의 다섯 잔여 항목을 순차 구현하도록 요청했다.

1. 모의·Gazebo 임무와 이벤트를 MySQL에 영속화하고 기존 임시 SQLite를 원본 보존 후 이전한다. 소유권 상실 시 자동 재연결로 잠금을 우회하지 않고, 트랜잭션과 재시작 복구를 확인한다.
2. 저장된 지도에 격리 Gazebo의 최신 `map` 좌표를 표시하고, 정지된 clock·오래된 TF는 미확인으로 표시한다. 실제 로봇 명령이나 실제 위치 연결은 포함하지 않는다.
3. 읽기 전용 DB 탐색기에 임무 및 상태 이력을 추가한다.
4. 루프백·SSH 터널 모델을 유지하며 조회자와 운영자의 로그인 및 임무 쓰기 권한을 분리한다. 실제 로봇 제어 권한은 포함하지 않는다.
5. MySQL 소켓 장애 복구와 서비스 재시작·DB 장애·로그인·브라우저 및 시뮬레이션 통합을 검증한다. 실제 재부팅과 장시간 안정성은 별도 시험 결과가 없는 한 완료로 주장하지 않는다.

검증 결과는 `prd/web-control-completion-test-plan.md`에 기록한다.

임무 목록과 DB 탐색기의 임무·이력 페이지는 시각과 ID(이력은 버전 포함)를 묶은 커서를 사용한다. 조회 도중 새로운 최신 기록이 삽입되어도 이미 조회한 페이지 경계가 밀리지 않는다. 기존 offset API는 호환성 목적으로 남아 있으며 같은 보장은 없다. MySQL 잠금은 단일 DB 세션이 소유하며 세션이 끊기면 해당 관리자는 연결을 재사용하지 않는다. 복구 시 진행 중 임무는 중단으로 기록하고 자동 재실행하지 않는다.
