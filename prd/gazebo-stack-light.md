# PRD 초안: Gazebo 경광등 점검

상태: 사용자 승인(2026-11-16). 기존 임무 관리 PRD의 점검 단계를 구체화하며 실기 구동 승인이 아니다.

## 목표와 범위
- 격리된 Gazebo 환경에 빨강·노랑·초록 세 구간의 점검 대상을 두고, 가상 RGB 카메라 영상으로 각 구간의 상태를 판정한다.
- 대시보드에서 Gazebo 점검 임무를 만들고 주행, 영상 확보, 판정, 결과를 확인한다. 기존 Gazebo 주행 임무는 별도로 유지한다.
- 처음에는 시뮬레이션에서 위치가 알려진 대상과 고정 카메라 시점을 사용한다. 실제 물체 일반 검출이나 YOLO 학습은 포함하지 않는다.
- 색상별 결과는 `on`, `off`, `blinking`, `unknown`으로 표현한다. 깜빡임은 충분한 시간에 걸친 영상 표본으로만 판단한다. 대상이 보이지 않거나 영상이 오래됐거나 표본이 부족하면 `unknown`이다.
- 점검 수행의 성공과 발견한 이상 상태는 분리한다. 주행만 성공했거나 판정에 필요한 관측이 없으면 점검 임무를 성공으로 표시하지 않는다.

## 흐름과 경계
1. 별도의 시험 월드에 색별 점등 상태를 제어할 수 있는 모형을 배치한다. 기존 지도와 기본 월드는 보존한다.
2. 격리 시뮬레이션의 `/depth_cam/color/image_raw` 영상과 명시적인 대상 영역을 사용해 판정한다. 프레임 시각·개수·관측 시간과 각 색의 결과를 근거로 남긴다.
3. 기존 Gazebo 실행기를 확장하되 주행 결과 확인 뒤 점검을 수행한다. 준비 실패, 영상 부재·오래된 영상, 판정 불가, 취소 및 타임아웃을 분리해 기록한다.
4. 화면에 실행 모드, 주행과 점검 단계, 색별 결과 및 판정 불가 사유를 표시한다. 저장 구조의 변경이 필요하면 기존 임무·이력과 호환되게 처리한다.

## 제약과 대안
- 실제 카메라·로봇을 구동하거나 실제 임무를 활성화하지 않는다. ROS 및 Gazebo 격리는 기존 주행 시험과 동일하게 유지한다.
- 고정 영역 판정은 구현과 검증이 간단하지만 카메라 자세와 대상 위치 변화에 취약하다. 실제 환경 적용에는 별도의 대상 검출, 노출·조명 보정, 실측 데이터와 검증이 필요하다.
- 단일 프레임의 밝기만으로 깜빡임이나 정상 여부를 추측하지 않는다. 실제 임계값과 성능은 시뮬레이션 결과로 일반화하지 않는다.
- 실제 장비의 정상 색상 조합과 이상 분류 규칙은 아직 정해지지 않았다. 첫 단계는 관측된 색별 상태만 제공한다.

## 완료 기준
- 시험 월드의 점등·소등·깜빡임 영상에서 판정 및 근거를 확인하고 영상 부재와 불충분 표본이 성공으로 표시되지 않는다.
- 격리 Gazebo에서 대시보드 임무 생성부터 주행·점검 결과 기록까지 검증한다. 취소와 재시작, 실패도 별도로 확인한다.
- 시험 결과는 시뮬레이션 한정으로 기록하며 실제 장비 성능과 전체 Mission BT 완료를 주장하지 않는다.
