# PRD: 팔 제어 경로 확정 + 접촉 파지 (로드맵 5단계)

신뢰 수준: **계획**(2026-10-11 작성, 구현 전). 상위: `docs/ROADMAP.md` 5단계, `docs/PLAN_ARM_TO_MVP.md` 5단계. 시험: `prd/arm-control-path-test-plan.md`.
이 문서의 수치 중 **측정하지 않은 것은 "미정(측정 후)"로 두며 확정값으로 읽지 않는다.**

## 1. 목표 / 비목표
**목표**: MoveIt이 팔·그리퍼를 움직이는 경로를 하나로 확정하고, 3 cm 블록을 집을 수 있는 **접촉 파지 Action**을 같은 시리얼 경로(base_node) 위에 만든다.
**비목표(이번 범위 밖)**: ros2_control `hardware_interface` 전환, base_node 분리, 새 제어 프레임워크, 인식(7단계), Pick & Place 전체(8단계), 3 cm 큐브 이외 물체의 파지 프로파일.

## 3. 현재 구현 상태 (확인한 사실)
- **폴링**: `arm_poll_hz`는 *서보 하나씩 읽는 타이머 주기*다. 한 틱마다 서보 하나에 읽기 요청을 보내고 6개를 돌아가므로 **각 서보의 갱신 주기 = 6 / arm_poll_hz**다(5 Hz → 서보당 1.2 s, 12 Hz → 0.5 s, 20 Hz → 0.3 s). 기본값 5.0(`base.yaml:78`, `base_node.cpp:184`). **12 Hz는 2026-10-06 실기에서 실제로 썼다**(`src/jetrover_manipulation/README.md:40`, `-p arm_poll_hz:=12.0`로 왕복 4/4 성공). 다만 12 Hz에서의 서보별 응답률·누락률·IMU 영향은 **정량 측정한 적이 없다**(T1이 그것을 한다). `/joint_states`도 같은 주기로 캐시값을 발행한다.
- **관절 피드백의 신선도**: `/joint_states` 헤더 시각 하나만 있고 **관절별 갱신 시각이 없다**. base_node는 마지막 읽은 값을 계속 발행하므로, 응답이 끊긴 서보도 최신처럼 보인다. 브리지의 `state_timeout_s`는 메시지 전체 시각만 본다.
- **브리지(`trajectory_bridge.py`)**: 팔·그리퍼 FJT 서버 2개, 계획 전체 사전 검증(유한값·관절 한계·스텝), 시작 자세 확인, 추종 지연 0.4 rad 초과 시 중단, 취소/실패 시 현재 자세 hold. 문제점: ① `_busy`는 잠금 없는 bool이라 목표 수락 콜백과 실행 사이에 **경쟁 조건**이 있고(ReentrantCallbackGroup + 4 스레드), ② 실행 중 예외가 나면 `_busy`가 True로 남을 수 있으며(try/finally 없음), ③ 실패 시 hold가 "현재 위치로 명령"이라 **파지 중 그리퍼에 쓰면 조임을 푼다**.
- **base_node 팔 경로**: `arm/command`·`arm/command_timed`는 서보별 데드밴드 보정(`arm_deadband_overshoot` [2,1,2,2,1,2])을 적용하고 읽기 피드백 보정(`arm_feedback_trim_ids` [1..5], **그리퍼 제외**)을 한다. 그리퍼(ID 10)에는 이동 방향으로 +2 눈금이 더해지는 보정만 걸린다.
- **접촉 파지(시험 도구에만 있음)**: `tools/stm32_diagnostics/rrc_m4_io_test.py`의 `grasp-levels`: 12 눈금씩 닫으며 읽은 위치가 명령을 따르지 않으면(지연 > 8, 같은 명령에서 위치 불변) 접촉으로 판단, 접촉 후 +16 조임. 3 cm 큐브 접촉 위치 519~527, 닫힘 끝 693, 열림 끝 ≤125(안전 클램프 100~900). **서보는 힘·전류·부하를 읽을 수 없다**(프로토콜: 위치·전압·온도·토크 상태만). 서보 온도 안전 기준 80 ℃(서보 자체 차단 85 ℃).

### R4. 안전 요구 (파지 상태 기계에 포함)
- 서보 온도: 시작 전·중에 ID 10 온도를 읽어 **80 ℃ 이상이면 시작 거부 / 진행 중이면 중단 후 조임 해제**.
- 타임아웃: 파지 전체 제한 시간(**미정(측정 후)**, 초안 8 s), 응답 누락 연속 N회(미정)이면 중단.
- 이동 범위: 안전 클램프 100~900 유지, 조임 목표는 접촉 위치 + squeeze가 닫힘 끝(693) 이하일 때만.
- **실패/이상 시 정책은 상태에 따라 나눈다**(옛 초안 "무조건 접촉 위치까지 풀기"는 들고 있는 물체를 떨어뜨릴 수 있어 폐기):

| 발생 시점 | 정책 |
|---|---|
| CLOSING/SQUEEZE (아직 안 들어 올림, 지면·작업면 근처) | 취소·타임아웃·응답 누락·고온 → **접촉 위치까지 풀고 실패 보고**(계속 밀지 않음). 열어도 물체는 아래에 있다 |
| HOLDING + 물체가 **지면/작업면 가까이**(들어 올리기 전 또는 내려놓은 직후) | 이상 시 팔·베이스 이동 중지 후 안전하게 열기 허용 |
| HOLDING + **들어 올린 상태**(팔이 pregrasp 위치를 벗어남) | **자동으로 열지 않는다**: 팔·베이스 이동 중지, 그리퍼는 마지막 조임 유지, 경고와 `arm/grasp_state`에 사유 게시, **안전한 내려놓을 위치로 이동 후 해제하거나 사용자 개입**을 기다린다 |
| 80 ℃ 이상 (고온) | 새 파지·새 이동 시작 거부, 진행 중 정상 작업은 **중단**한다. 단 **"계속 잡고 있어도 안전하다"고 가정하지 않는다**: 서보 자체 차단이 85 ℃이고 차단되면 토크가 풀려 떨어진다 → 유지 가능 시간·온도 상승률은 T5/T6에서 따로 측정해 확정(**미정(측정 후)**), 그때까지 들어 올린 상태에서의 고온은 "사용자 개입 요청 + 내려놓기" |
| 시리얼 단절로 풀기 명령도 못 보냄 | 서보 자체 거동에 맡긴다(best-effort, AGENTS.md 정지 보장과 같은 한계) |

"지면 근처"/"들어 올린 상태"의 판정 기준(관절 자세 또는 단계 플래그)은 **미정**: 파지 Action이 호출자(MoveIt 시퀀스)로부터 `lifted` 상태를 받는지, 관절 자세로 직접 판정하는지는 T5 설계에서 정한다.
- 로그: 상태 전이, 접촉 위치, 지연, 온도, 중단 사유를 기록.

### R5. 파지 Action
- 인터페이스: **전용 Action `arm/grasp`**(취소·피드백). goal = 프로파일 이름(`cube3cm`) 하나, feedback = 상태·그리퍼 위치·접촉 위치·지연·온도, result = 성공/실패 사유·접촉 위치·최종 위치. 별도 메시지 타입이 필요하면 새 인터페이스 패키지 대신 우선 `control_msgs`/표준 타입의 조합 가능성을 검토하고, 안 되면 PRD를 개정해 결정한다(**미정**). 위치 목표 열기/닫기는 기존 `gripper_controller`(FJT) 그대로이며 **`GripperCommand`는 이번 범위에서 쓰지 않는다**(D4) — `max_effort` 의미를 서보가 지킬 수 없다.
- 해제: **명시적 Release 명령**(`arm/release` 서비스 또는 같은 Action의 해제 goal, 형태는 T6 설계에서 **미정**). HOLDING에서만 의미가 있고, Release가 끝나야 ID 10 소유권이 IDLE로 반환된다.
- 상태 기계(`GraspStateMachine`, 순수 C++, `src/jetrover_base/include/jetrover_base/grasp_state_machine.hpp`): IDLE → CHECK(온도·위치 읽기) → CLOSING(작은 스텝, 접촉 대기) → CONTACT(접촉 확정 규칙) → SQUEEZE(프로파일 눈금) → **HOLDING**(`arm/grasp` 성공 후에도 유지, 소유권 유지) → RELEASING(Release 명령 또는 4절 R4의 안전 해제) → IDLE, 실패는 FAILED → IDLE. 시간·읽기값·명령을 입출력으로 받아 단위 시험한다.
- 프로파일: `cube3cm` 하나(접촉 스텝 12, 지연 8, squeeze **+16**, 접촉 창, 타임아웃, 온도 한계). **+16은 3 cm 큐브 시험값이며 다른 물체의 기본값이 아니다.**
- 변경: 신규 `grasp_state_machine.hpp/cpp`, `base_node.cpp`(Action 서버·타이머), `base.yaml`(프로파일 파라미터), 테스트 `test_grasp_state_machine.cpp`.
- 통과 기준: 3 cm 큐브 파지 **미정(측정 후; 초안 10/10, 관절 1 ±10° 흔들기 유지)**, 취소·타임아웃·응답 누락·고온에서 모두 R4 동작.

### R6. 배타 제어 (D5)
- 현재: 없음. `arm/command` 경로는 ID 10을 언제든 쓸 수 있다.
- **상태별 제어권**(파지 상태 기계가 소유):

| 상태 | 관절 1~5 | 그리퍼 ID 10 |
|---|---|---|
| IDLE | 기존대로 허용 | 기존 `gripper_controller`(FJT)·`arm/command` 허용 |
| CHECK / CLOSING / CONTACT / SQUEEZE | 이동 명령 **거부**(접촉 감지·조임 중에 팔이 움직이면 판정이 불안정) | 파지 상태 기계만 |
| **HOLDING** | **MoveIt 이동 허용**(들어 올려 옮겨야 하므로) | **파지 상태 기계가 소유 유지**, 다른 ID 10 명령 거부 |
| RELEASING | 이동 명령 거부 | 해제 로직만 |
| FAILED | 거부(원인 보고 후 IDLE 복귀 전까지 짧게) | 상태 기계만 |

- 변경: base_node가 위 표대로 `arm/command`·`arm/command_timed`·홈 이동·토크 명령을 판정한다(ID 10 포함 여부 + 관절 1~5 이동은 상태에 따라). 브리지 `gripper_controller` 목표도 IDLE이 아니면 거부(base_node 상태 토픽 `arm/grasp_state` 구독) — 두 겹.
- 통과 기준: ① HOLDING 중 ID 10 명령 20회 주입 → 20회 거부, 조임 위치 변화 ±2 눈금 이내 ② HOLDING 중 MoveIt 팔 이동 허용(관절 1~5 이동 성공) ③ CLOSING/SQUEEZE/RELEASING 중 관절 이동 명령 거부 ④ Release 후에만 FJT 그리퍼 명령이 다시 통한다.

### R7. 기존 브리지 안전성
- ① **관절별 신선도**: R1의 `arm/servo_stats`(또는 `/joint_states`에 관절별 시각 병행)로 브리지가 개별 관절 데이터가 `state_timeout_s`보다 오래되면 거부한다. 변경: `trajectory_bridge.py`, `base_node.cpp`.
- ② **목표 수락 경쟁 조건**: 수락 콜백에서 잠금 아래 `_busy`를 원자적으로 확보하고, 실행은 try/finally로 해제. 팔·그리퍼 동시 목표 요청 시험을 단위로 만든다(`test_bridge_logic.py`).
- ③ **hold 정책**: 그리퍼는 hold 명령을 보내지 않는다(파지 상태 기계가 소유). 팔 관절 hold는 유지.
- 통과 기준: 동시 목표 1000회 중복 수락 0, 예외 후 `_busy` 해제, 한 관절만 오래된 입력 거부.

### R8. 기존 피드백 보정과의 충돌 방지
- 읽기 피드백 보정은 이미 그리퍼를 제외한다(`arm_feedback_trim_ids`). 유지하고 **회귀 시험으로 고정**한다. 그리퍼에 걸리는 데드밴드 +2는 파지 중에는 우회한다(상태 기계가 보정 없이 직접 명령).
- 통과 기준: 파지 중 보정 재시도 로그 0, 파지 후 관절 1~5의 보정 동작 변화 없음(오차 ±1~2 펄스 유지).

### R9. MoveIt 실기 통합 (마지막)
- 순서: home → pregrasp(관절 목표) → 파지 Action → 들기(+10 cm 상당 관절 목표) → 놓기 → 열기 → home. 인식 없이 정해진 위치의 큐브로.
- 통과 기준: 기존 게이트 유지 — 이름 자세 간 이동·관절 목표 10회 연속 성공(관절 오차 ≤ 0.05 rad), 그리퍼 열기/닫기 10/10, 시리얼 오류/IMU 끊김 0. 파지 시퀀스 성공률은 **미정(측정 후)**.
- 서보 온도: 시퀀스 반복 중 80 ℃ 미만 유지(관절 3 홈 자세 발열은 별도 위험으로 기록됨).

## 5. 순서 (사용자 지시)
폴링 벤치마크(R1) → 접촉 감지 검증(R3) → 파지 Action(R5·R4·R6·R8) → MoveIt 실기 통합(R9). R7(브리지 안전성)은 R1의 `arm/servo_stats`가 생기면 바로, R2는 R1 결과에 따라 만들거나 만들지 않는다. **PRD 승인 전에는 구현·대규모 리팩터링을 하지 않는다.**

## 6. 위험
| 위험 | 대응 |
|---|---|
| 위치 정체를 접촉으로 오판(빈 닫기, 응답 누락) | R3 시험, 제한 모드(접촉 창), 응답 누락 연속 시 중단 |
| 폴링을 빠르게 하면 IMU/주행 명령에 영향 | R1에서 IMU 수신률·`cmd_vel` 지연을 같이 측정, 채택 기준에 포함 |
| 조임 지속으로 그리퍼/관절 1 과열(오늘 그리퍼 53 ℃, 관절 1 61 ℃까지) | 온도 한계, 파지 시간 제한, 풀기 |
| 파지 중 다른 명령이 조임을 풀거나 더 조임 | R6 배타 제어(두 겹) |
| 액션 인터페이스가 프로파일을 못 담음 | R5에서 별도 인터페이스로 개정 |
| +16이 다른 물체에서 너무 약하거나 강함 | 프로파일 이름으로 분리, 일반화 금지 |
