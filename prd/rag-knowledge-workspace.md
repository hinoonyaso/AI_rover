# PRD: JetInspect-M 지식 검색과 벡터 DB 관제

## 목표와 범위
작업자가 대시보드에서 승인된 로봇 문서와 점검 이력을 근거로 질문하고 출처·날짜·신뢰 수준을 확인한다. 벡터 DB의 문서·청크·색인 상태와 검색 결과를 대시보드에서 조회하고 운영자가 허용된 자료만 색인·갱신한다. 현재 프로젝트의 활용처를 정리하되 동작·성능은 검증 전까지 계획으로 취급한다.

## 활용처와 우선순위
1. 문서 기반 장애 진단: LiDAR/IMU/카메라 연결, ROS, SSH 및 실제 원인과 가설 구분.
2. 센서·구동·팔 보정: 절차, 단위, 장비별 설정과 적용·복구 방법의 출처 확인. 실제 적용은 기존 명시적 기능만 사용.
3. 임무·설비 점검: 설비별 매뉴얼 및 점검 보고서 해석, 과거 반복 증상 검색. 현장별 판정은 해당 매뉴얼에 근거해야 한다.
4. 정비·운영 이력: 임무 결과, 오류 이력, 변경 기록을 기간·장비별로 조회하고 연관 보고서를 검색.
5. 개발 지원: 아키텍처, ROS 토픽/프레임, 펌웨어 프로토콜, Gazebo 시험 및 최신 확인 상태 조회.
6. 음성 안내: 동일한 검색 API와 출처를 음성 파이프라인에서 재사용. 음성 입력·출력 통합은 별도 단계.
7. 지도·장소·설비 의미 검색: 후보를 찾는 보조 기능. 확정 좌표와 상태는 구조화 데이터의 검증된 값에서 가져온다.

## 경계
실시간 배터리·센서·위치·임무 상태와 정확한 집계는 ROS/기존 MySQL API를 사용한다. RAG 결과는 센서 판정, 안전 판단, 모터·팔 제어 또는 자동 설정 변경에 사용하지 않는다. 명령은 기존 검증된 별도 경로를 거친다. 문서 내 지시는 신뢰하지 않는 데이터이며 근거 부족 시 답변을 유보한다.

## 구조와 결정
대시보드/향후 음성 → 인증 API → 허용 자료 색인·검색 → 별도 로컬 Qdrant 벡터 DB → 근거 확인 → 로컬 LLM → 답변과 출처. 운영 데이터는 기존 MySQL에 유지한다. Qdrant는 ARM64를 공식 지원하고 서버를 로컬에 분리할 수 있어 후보로 채택한다. Chroma 임베디드나 pgvector도 가능하지만 각각 프로세스 내 운영 결합 및 기존 MySQL과 별도 PostgreSQL 도입이 발생한다. Jetson 실제 자원 사용과 호환성은 미검증이다. Qdrant는 루프백 전용으로 두고 인증·권한은 대시보드 API에서 처리한다.

한국어·영어 임베딩 모델은 실제 검색 품질, 메모리와 응답시간을 측정해 확정한다. 모델/버전/차원이 다른 벡터는 혼합하지 않고 새 컬렉션 구축 후 전환한다. 사용자 동의 없는 외부 전송은 없다. 기존 로컬 Qwen 모델은 생성 후보이나 근거 준수 성능·동시 부하는 미검증이다.

수집은 승인된 문서 경로와 확장자 허용목록으로 제한한다. `.env`, 자격증명, 개인키, 데이터베이스 원본과 임의 로그는 자동 수집하지 않는다. 심볼릭 링크와 경로 이탈을 차단한다. 문서별 출처, 변경 시각, 버전, 확정/추정/계획 및 청크 식별자를 저장한다. 색인 상태·실패를 표시하고 원본을 수정하거나 삭제하지 않는다. 재색인 중에도 이전 정상 색인을 유지한다. 조회자는 읽기, 운영자는 색인 변경을 사용한다.

## 단계
1. PRD·시험 계획 및 활용처 정리.
2. 로컬 DB·모델 자원/호환성 검증 및 선택, 의존성·운영 방식 결정.
3. 안전한 문서 수집, 청크·메타데이터, 색인 생성과 재색인·복구.
4. 검색 API와 출처 기반 답변, 권한·제한·실패 처리.
5. 대시보드 질의 및 DB 탐색·색인 관리.
6. 한국어 평가, 동시 부하·복구 검증; 이후 음성 및 이력 연동.

## 완료 기준
허용 문서만 색인되고 변경·삭제가 색인에 반영된다. 질의가 출처 및 신뢰 수준과 함께 관련 근거를 반환하고 근거 없음을 표시한다. 조회·운영 권한을 구분한다. Qdrant 장애와 모델 부재를 명확히 표시하고 기존 관제는 정상 동작한다. 한국어 대표 질의와 실제 Jetson 동시 부하에서 시험 계획을 충족한다. 대시보드 기능과 실제 ROS 데이터·음성 통합 여부를 구분해 기록한다.

## 2026-11-17 구현 시 결정
Docker 소켓 접근이 불가능해 Python Qdrant 로컬 모드를 사용한다. 별도 네트워크 서비스 없이 전용 디렉터리에 독립 벡터 DB를 보관하고 대시보드 프로세스 하나가 소유한다. 다중 서버 프로세스는 같은 DB를 동시에 열 수 없다. Sentence Transformers 다국어 MiniLM의 FastEmbed ONNX 양자화 모델을 CPU 두 스레드로 사용한다. 생성은 기존 로컬 Qwen 1.7B를 별도 프로세스로 사용한다. 재색인 전 세대는 보존하며 자동 정리는 구현하지 않았다. 설계 당시의 루프백 서버 방식에서 변경한 이유는 Docker 권한 및 시스템 설정 변경을 피하기 위해서다.
