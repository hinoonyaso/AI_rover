# PRD: 정밀 접근 경로 안전 검사

- 작성 2026-11-11. 상태: 시뮬레이션 전용 실험 구현; 반복·회귀·실기 검증 전. 체크리스트 9.4 후속.

## 목표와 근거
정밀 접근의 마지막 이동과 회전 중 차체가 장애물에 가까워지는 위험을 줄인다. D11 시뮬레이션에서 정밀 접근 중 발 간격이 8→2 cm로 감소했다(`docs/benchmarks/navigation/foot_clearance_sim_20261030.md`, 체크리스트 9.4). 현재 제어기는 local costmap을 확인하지 않고 `/cmd_vel_nav`로 명령하며 속도 평활기·collision_monitor는 그대로 경유한다. 이들은 감지 범위·지연의 한계가 있으므로 별도의 검사도 안전을 보장하지 않는다.

## 범위와 제약
- 로컬 costmap과 TF가 신선하고 사용 가능할 때만 현재 자세에서 명령으로 예상되는 차체의 이동·회전 영역을 반복 확인한다. 장애물, 미지 영역, 지도 경계 밖, TF·costmap 오류/오래됨은 정지 후 실패로 처리한다. 취소와 종료에서도 정지한다.
- costmap은 `/local_costmap/costmap`의 `nav_msgs/OccupancyGrid`(값 0~100, 미지 -1; Nav2 내부 0~255 cost와 혼동 금지), 좌표계는 메시지 헤더를 따른다. 기본 설정은 odom, 해상도 0.025 m, 전체 지도 발행 2 Hz다. 현재 자세와 목표의 map→costmap 변환, TF 시각·유효성, QoS 및 ROS/sim 시간 정지 시 수신 경과 시간은 실제 환경에서 확인한다. 발행되고 있어도 센서 입력이 유효한지는 별도 문제다.
- 회전·메카넘 옆/대각 이동을 포함하는 **차체 전체의 swept footprint**를 검사한다. footprint는 실제 local costmap 설정과 padding을 사용하며 불일치 시 실패한다. 격자 셀과 다각형의 접촉·회전 중간 자세까지 보수적으로 다룬다. inflation 셀의 임계값은 별도 실험을 거쳐 정한다. lethal만 검사하면 충분한 여유가 확보된다는 가정은 금지한다.
- 최초 구현은 시뮬레이션 전용 실험 설정에서만 켠다. 공식 설정 및 실기 동작 변경은 시험 결과와 별도 사용자 승인을 거친다. 기존 collision_monitor와 stop 경로를 유지한다.
- 지도 갱신 간 이동, TF/센서 지연, 속도 평활기와 물리적 정지 거리까지 포함한 검사 지평·여유는 측정 전 미정이다. 지평이 검증되지 않으면 주행을 허용하지 않는다. 이동 장애물이나 시야 밖 장애물을 예측할 수 없고, 비용 지도가 비어 있어도 안전의 증거가 아니다.

## 설계 후보와 선택
1. **권장 후보:** local costmap을 구독해 현재 명령의 가까운 미래 swept footprint를 매 제어 주기 검사. 비동기적으로 최신 전체 지도를 보관하고, 추후 종료·취소 시 안전하게 해제한다. 장점은 기존 데이터 재사용과 반복 검사, 단점은 복잡한 다각형/격자 처리 및 stale/시간/QoS 문제. 지도와 footprint의 실제 배포 타입과 지연을 먼저 검증한다.
2. 목표점 또는 중심선만 검사: 회전·차체 모서리를 빠뜨려 기각.
3. Nav2 충돌 검사 API/기존 제어기에 위임: footprint 구현 재사용의 장점이 있으나 현재 Jazzy에서 호출 방식·주기·실패 동작 확인 전이므로 대안으로 조사한다. Jazzy에 Python `nav2_simple_commander.footprint_collision_checker`가 있으나 설치된 구현은 다각형 테두리의 선만 검사한다. 내부 셀과 자세 사이 swept 영역은 보장하지 않으므로 단독 사용하지 않는다. 필요한 보완을 검증한 경우에만 재사용한다.
4. collision_monitor만 사용: 기존 방어층이지만 D11에서 충분한 간격이 나오지 않았으므로 단독 해결책으로 채택하지 않는다.

## 인터페이스 및 실패
- 입력: 목표 `NavigateToPose`(map), 실제 base TF, local OccupancyGrid와 설정된 padded footprint, ROS 시간·수신 단조 시계. TF는 검사에 쓰는 costmap 프레임과 시각을 명시하고 변환 불가 시 실패한다.
- 출력: 기존 `/cmd_vel_nav`와 action 결과. 막힘과 지도/TF 무효는 서로 다른 새 오류 코드 후보(9104/9105, 충돌 여부 확인 후 확정)로 구분한다. 막힘 감지 때 0 속도 발행 후 abort; BT의 기존 1회 재시도와 오류 전달을 검증한다. 지도 비우기나 자동 우회는 하지 않는다.
- 센서/지도 최신성 판단 수치, 비용 임계값, 최소 발 간격, 반복 횟수 및 정지 지연은 기존 벤치마크와 측정에 근거해 확정한다. 특히 ROS 시계 정지·미래 타임스탬프·수신 중단을 실패로 처리한다.

## 비범위
실기 운행, footprint_padding 공식 적용, 기존 Nav2/collision_monitor 교체, 전역 경로 계획, 사각지대 해결, AprilTag.

## 완료 기준
시험 계획의 단위·통합·시뮬레이션 기준을 만족하고 결과·한계를 기록한다. 실기 검증과 공식 반영 전까지 기능 전체는 `[~]`로 둔다. 실제 모터 구동은 별도 승인과 안전 절차가 필요하다.
