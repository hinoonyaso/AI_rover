# PRD: 읽기 전용 운영·센서 대시보드

신뢰 수준: 사용자 승인 계획 (2026-11-15). 구현 및 실기 검증을 완료했다는 뜻이 아니다.

## 목표
로봇 동작이 어려운 현재 상황에서 로봇을 움직이지 않고 진행할 수 있는 관제 화면을 먼저 만든다. 개발자가 Jetson의 운영 상태와 사용 가능한 센서 수신 상태를 확인하고, 데이터가 없거나 오래된 경우를 구분할 수 있게 한다. 기존 로드맵의 대시보드 순서를 앞당기는 이유는 이 목적에 한정한다.

## 현재 상태
`tools/ops/`에 FastAPI, React/Vite, MySQL 기반 읽기 전용 화면이 있다. 호스트 지표와 DB 상태, 배터리 전압, IMU·LiDAR·카메라 토픽 수신율, 운영 이벤트를 표시한다. ROS 모니터는 토픽을 구독해 파일에 상태를 기록하고 API는 이를 읽는다. 현 화면은 5초마다 API를 조회한다. 상세와 기검증 범위는 `tools/ops/README.md` 참고. ROS 실제 센서 및 재부팅·장시간 부하는 미검증이다.

## 범위
- 호스트 CPU·메모리·저장 공간·온도, DB 연결, ROS 모니터, 배터리 전압과 센서별 수신 상태를 읽기 전용으로 표시한다.
- 측정 시각 또는 경과 시간, 미수신·오래된 데이터·서버 연결 오류·DB 오류를 해당 정보와 함께 표시한다. 센서 미수신을 로봇 고장이나 로봇 전체 오프라인으로 단정하지 않는다.
- 기존 `/api/metrics`의 CPU·메모리·저장 공간·온도 이력과 `/api/events`의 최근 운영 이벤트를 표시한다. 빈 기록과 DB 오류를 구분한다.
- 로봇 하드웨어 없이 가상 센서 데이터와 오류 상황으로 화면과 API를 검증한다. 실제 센서 확인은 장비 사용이 가능할 때 별도 L2 검증으로 기록한다.
- 실행 방법, 데이터 출처와 제한, 검증 결과를 기존 운영 README에 반영한다.

## 비범위
- 모터·팔 제어, ROS bringup, 임무 실행/취소, 비상정지 및 물리적 구동 시험.
- 지도·위치·카메라 영상·인식 결과·미션 및 점검 이력 연동, 원격 사용자 인증/외부망 공개, RAG, DB 이전.
- 실제 센서 연결, 재부팅 및 장시간·동시 부하 시험을 하드웨어 없는 개발 단계의 완료 조건으로 가정하지 않는다. 이들은 별도로 미검증 상태를 유지한다.

## 제약 및 구조
- `AGENTS.md` 안전 규칙을 따른다. 관제 프로세스는 읽기 전용이며 발행·서비스 호출·액션 전송을 통해 로봇을 움직이지 않는다. 수신 없음은 안전 상태의 증거가 아니다.
- 기존 localhost 바인딩과 원격 SSH 터널 방식을 유지한다. 인증 없는 서버를 외부 인터페이스에 노출하지 않는다.
- 기존 FastAPI·React(JavaScript)·MySQL과 ROS 모니터 구조를 우선 활용한다. 현재 5초 폴링을 유지하고 지연이나 부하 측정으로 필요성이 확인될 때만 WebSocket을 별도 검토한다. TypeScript 전환과 DB 교체는 선행 조건이 아니다.
- 센서의 단위·수신 시각·신선도와 오류 표현을 API와 화면에서 일관되게 정의한다. 기존 스냅샷 8초 및 배터리 10초 만료 기준은 출발점이며, 변경이 필요하면 근거와 시험을 기록한다. 시간 역행 등 비정상 시각은 유효 데이터로 취급하지 않는다.
- 서버/DB 중단 테스트는 격리된 테스트 환경이나 대체 데이터로 수행하며 기존 운영 데이터는 보존한다.

## 작업 분해안 (진행 상태는 체크리스트 19절에서 관리)
1. 기존 API·화면·ROS 스냅샷의 데이터 계약과 오류/신선도 기준을 정리한다.
2. 운영 상태와 센서별 데이터·시간·미확인 상태를 표시한다.
3. 서버, ROS 모니터, DB 장애 및 복구 상태와 빈 기록을 구분한다.
4. 기존 시스템 지표 이력과 운영 이벤트를 표시한다.
5. 하드웨어 없는 자동/수동 검증을 실행하고 README에 사용법 및 결과를 기록한다.
6. 장비를 사용할 수 있을 때 구동 없이 실제 센서를 대조하고 결과를 별도 기록한다.

## 완료 기준
- 최신 호스트 지표, 배터리 전압, 각 센서 수신율과 데이터 시각/경과 시간이 화면에 보인다. 실제 값을 사용할 수 없으면 미확인으로 보인다.
- 가상 데이터로 정상 수신, 센서 미수신·만료, ROS 모니터 중단, 서버 연결 실패 및 복구, DB 실패 및 복구, 기록 없음이 구분됨을 검증한다.
- 기존 API 이력이 정상일 때 표시되고 기록 없음과 DB 실패가 구분된다. 서버 장애 중 이전 값은 오래된 값임을 알 수 있다.
- 프론트엔드 빌드 및 관련 테스트가 통과하고 localhost 접근 및 제어 기능 부재를 확인한다.
- 하드웨어 없는 범위의 완료와 실제 센서 L2 검증 여부를 따로 기록한다. 실기 검증이 남아 있으면 전체 항목을 실기까지 완료한 것으로 표시하지 않는다.
