# PRD: 음원 방향 인식 (DOA)

- 작성 2026-11-11. 상태: 다채널 입력용 실험적 SRP-PHAT 구현·합성 시험 완료. **실제 8채널 전달·채널/방향 보정 및 실기 DOA 미완료**.

## 목표
6개 마이크가 있는 배열로 들리는 소리의 수평 방향을 확인한다. 로봇 정면을 0°, 왼쪽을 양의 각도로 표시하는 것을 목표로 한다(ROS REP-103). 로봇을 움직이는 기능은 포함하지 않는다.

## 현재 장치와 제약
- 2026-11-11 ADB 읽기 전용 조사: R818 내부 `card 1 / device 0` (`sndac107.1-0036`)이 `S16_LE`, 16 kHz, **8채널**로 RUNNING이다. `/data/build/demo_vtn` PID 1807이 장치를 사용하고 캡처 subdevice는 1개, 사용 가능 0개다. 이는 보드 내부의 다채널 캡처를 확인한 것이며 채널별 마이크/참조 신호 배치와 Jetson으로의 실시간 전달은 아직 확인하지 않았다. 이 PID와 장치 번호는 부팅마다 바뀔 수 있다.
- 보드에 `/data/build/origin.pcm` 2,252,800바이트가 있으나 보드 시간으로 부팅 직후 생성된 기존 파일이며 형식·현재 입력과의 관계는 미확정이다. S16_LE 8개 슬롯으로 가정하여 보드 안에서 RMS만 계산했으나(약 3.3~3.4, 220.6/220.3) 이로써 채널 수·신호 의미는 증명되지 않는다. 파일은 복사·재생하지 않았다.
- ADB의 `exec-out` 및 `shell -T`는 보드의 제한된 ADB에서 실패했다. 현재 Jetson USB 오디오 외 다채널 스트리밍 경로, 재사용 가능한 덤프 API, 채널 순서와 마이크 동기화는 미확인이다. 실행 중인 캡처 프로세스 중단, 기존 파일 변경, 설정 변경 또는 펌웨어 변경은 하지 않았다.
- USB 오디오 `hw:CARD=XFMDPV0018,DEV=0`은 드라이버/USB descriptor 기준 S16_LE, 16 kHz, **모노 1채널만** 제공한다. `arecord -c 6`은 `Channels count non available`로 실패했다. ALSA `plughw`로 가짜 채널을 늘려도 독립 원시 채널이 생기지 않는다. 따라서 현재 오디오에서 GCC-PHAT의 마이크 간 시간차를 계산할 수 없다.
- `/dev/serial/by-path/platform-3610000.usb-usb-0:2.1.1.1:1.0-port0`에서 115200 8N1로 `a5 01 01 04 00 00 00 a5 00 00 00 b0`를 0.5초마다 수신했다. 이는 [R818 계열 음성 모듈의 핸드셰이크](https://docs.elephantrobotics.com/docs/Mercury_X1_en/6-SDKDevelopment/6.1-Python/6.1.7-VoiceFunction.html)와 정확히 일치해 마이크 제어 포트라는 강한 근거다. 제조사 [JetRover 문서](https://wiki.hiwonder.com/projects/JetRover/en/jetson-orin-nano/docs/9.Voice_Control_Course.html)는 시리얼로 깨우기 이후 각도 출력을 설명한다.
- [관련 iFlytek 프로토콜](https://aiui-doc.xf-yun.com/project-1/doc-108/)은 깨우기 이벤트의 각도를 설명한다. **일반 음향에 대한 연속 DOA 제공 여부는 확인되지 않았다.** 웨이크 각도는 사용자가 요청한 임의 소리의 연속 DOA와 같지 않다.
- 사용자가 마이크 USB 커넥터 쪽이 로봇 후면이라고 확인했다. 기기 각도 0°의 물리 방향과 증가 방향은 미검증이므로 로봇 좌표로 변환하지 않는다.
- 기존 음성 인식 패키지 `xf_mic_asr_offline`은 현재 작업 공간과 호스트 PC에서 찾지 못했다. 키워드·펌웨어 설정 상태는 미확인이다. 펌웨어 쓰기, 음성 자원 변경 및 모터 제어는 이 작업에 포함하지 않는다.

## 진단 구현
`tools/audio/r818_doa.py`는 명시 실행 시 마이크 시리얼을 열어 검증된 프레임의 확인 응답을 보내고, `aiui_event`의 `eventType=4`·`content.info.angle`에 유효한 숫자가 있으면 **기기 기준 깨우기 각도**만 출력한다. 녹음·발화 내용을 저장하지 않고, 로봇을 움직이지 않는다. 실제 장치의 핸드셰이크는 확인했으나 실제 깨우기 이벤트와 형식은 아직 확인하지 못했다. 합성 프레임 테스트는 구현 확인이지 실기 방향 정확도 검증이 아니다.

## 다음 단계
1. 제조사 자료/펌웨어 설정에서 현재 웨이크 단어와 실제 각도 이벤트 형식, 연속 DOA 또는 6채널 원시 출력 가능 여부 확인. 기존 설정을 변경하기 전 백업과 영향 확인.
2. 이벤트가 잡히면 정면·좌측·우측·후방에서 여러 회 측정하여 기기 각도 영점·증가 방향 및 정확도 검증. 원시 각도와 보정 값의 시각을 함께 기록.
3. 임의 소리의 연속 방향이 필요하고 현재 장치가 이를 제공하지 않으면 6채널 원시 데이터를 제공하는 장치나 검증된 장치 API가 필요하다. ROS 게시·상태·타임아웃은 인터페이스 확정 후 구현한다.

## 2026-11-11 다채널 DOA 계산기

`tools/audio/doa_core.py`(SRP-PHAT, 명시적 마이크 좌표·PCM, 무음·모호 입력 거부)와 `tools/audio/doa_stream.py`(16비트 WAV 또는 명시적 ALSA, 채널 매핑 JSON, JSONL 결과)를 구현했다. 예제 좌표는 합성 시험 전용이며, 보정 플래그도 사용자가 제공하는 값이다. 여섯 방향(0°, 45°, 90°, 180°, 270°, 358°) 합성 평면파·무음·동일 채널·잘못된 데이터, 채널 순서를 섞은 8채널 WAV 종단간 시험이 통과했다. Jetson에서 0.256초 합성 블록 30회 연산 중앙 6.37 ms, 최대 7.06 ms(다른 시스템 부하·ROS 통합 미측정). 현재 모노 USB에 8채널을 요청하면 오류로 중단하고 방향을 내지 않는다. 실제 장치의 채널 순서·물리 마이크 좌표·지연·잔향 및 정확도는 검증되지 않았다.

실시간 소스 조사: 보드의 `/data/build/demo_vtn`이 ALSA `hw:1,0`의 8채널을 독점한다. 그 프로세스의 PCM 장치 메모리 매핑은 보였으나 `/proc/1807/mem`을 통한 읽기 확인은 0바이트여서 사용할 수 있는 전달 경로를 확인하지 못했다. 해당 프로세스는 조사 후에도 RUNNING이었다. PID나 메모리 주소를 재사용하는 것은 금지한다. 보드의 기존 설정·프로세스는 변경하지 않았다.


## 2026-11-11 합성 잡음 추가 시험

정확한 가상 6마이크 위치(반지름 3.5 cm), 16 kHz, 0.256초 평면파, 12방향 × 5개 난수: SNR +10 dB에서 60/60의 오차 ≤10°(최대 1°), 0 dB에서 60/60(최대 5°), -10 dB에서 60회 중 58회 추정·2회 거부, 추정 중 56회 ≤10°(최대 15°). 신호 없는 독립 잡음은 기존 상대 피크 기준만 사용할 때 100회 중 92회 허위 방향을 출력했다. 실험적인 공간 일치도 기준 0.05를 추가한 뒤 별도 난수의 독립 잡음 200회 모두 방향 없음으로 판정했다. 합성 분포에 맞춘 기준이며 실제 마이크, 반사음·상관 잡음·여러 음원에서는 오탐과 누락 가능; 기준의 실기 보정이 필요하다. 실행 `python3 tools/audio/benchmark_doa_synthetic.py`.

실제 마이크 시험 준비를 위해 R818 점유 프로세스 및 복구 경로를 확인했다. `demo_vtn`과 `watch`가 실행 중이며 부팅 스크립트가 이를 실행한다. 프로세스를 멈추면 재시작 스크립트가 `demo.log`를 삭제할 수 있으므로 프로세스를 중단하지 않았다. 현재 내부 8채널의 외부 동시 접근 및 채널 매핑은 여전히 미확인이다.

## 2026-11-11 어레이 기능 및 빔포밍 추가 조사

R818 보드 설정을 읽기 전용으로 확인한 결과 `user_cfg.ini`의 `version=mic6_circle`, `vtn/vtn.ini`의 `cae_enable=1`, `beam=1`, `ivw_enable=1`이 설정되어 있다. 이 값은 설정 증거이며 동작 중 처리 결과나 정확도 증거는 아니다. 제조사 설명은 빔포밍·소음 억제·AEC와 별도 AEC 참조 신호 포트를 명시한다([제조사 소개](https://wiki.hiwonder.com/projects/JetRover/en/jetrover-jetson-nano/docs/13_ROS1-Voice_Control_Lesson.html)). 현재 스피커 경로의 참조 신호 연결 및 AEC 작동 여부는 미확인이다. 제조사 문서의 원본 오디오 내보내기 절은 M260을 명시하므로 이 R818에서 사용할 수 있다고 가정하지 않는다.

독립 6채널을 사용할 수 있을 때 적용할 오프라인 지연합 빔포머 `tools/audio/beamform_array.py` 및 WAV 도구 `beamform_wav.py`를 추가했다. 보정된 좌표와 동기 채널이 필요하고 합성 방향 음원으로만 검증했다. 현재 하드웨어에 적용되거나 실시간 집음되는 것은 아니다. 기존 SRP-PHAT 방향 추정은 별도 합성 회귀 통과했으며, 실제 입력·방향 보정 문제는 여전히 남아 있다.

## 2026-11-11 실제 내부 8채널 시험

사용자 입회하에 보드의 기존 캡처 프로세스를 잠시 중단하고 16 kHz S16_LE 8채널 12초를 녹음했다. 기존 로그를 사전 백업했으며 재시작 시 로그가 초기화되어 `/data/build/demo.log.before-array-probe`에 원본을 보존했다. 이후 `watch`, `demo` 및 보드 내부 캡처 RUNNING, Jetson USB 모노 입력 1초 정상 캡처를 확인했다. 모터는 움직이지 않았다.

0~5번 채널은 RMS 약 883~1078, 6~7번은 약 40~56이었고 0~5에는 유사하지만 완전히 동일하지 않은 신호가 있었다. 이는 마이크 채널이라는 가설을 뒷받침하지만 배선과 각 슬롯의 의미를 확정하지 않는다. 임의 순서·반지름 3.5 cm의 합성 좌표를 넣고 실기 녹음에 빔포밍과 DOA 계산이 실행되는 것을 확인했다. 이 좌표는 실제 배열에 맞게 검증되지 않았으며 계산된 각도는 물리 방향이나 정확도의 증거가 아니다. 채널 순서·기하 및 정면 기준 보정과 반복 방향 시험이 필요하다. 캡처는 일시적인 파일 방식이므로 연속 스트리밍은 아직 없다.

## 네 방향 실기 보정 탐색

사용자 준비 확인 후 정면·좌·우·후면에서 각각 10초씩 내부 8채널을 임시 캡처했다. 0~5번 채널의 시간차를 이용해 가상 유효 좌표를 추정해 `tools/audio/experimental_geometry_20261111.json`에 `calibrated=false`로 저장했다. 이 좌표는 실제 물리 위치의 측정값이 아니며 로봇 구동에 사용하지 않는다. 같은 보정 녹음에서는 각 위치 대체로 해당 방향 부근이었으나 오추정 및 거부가 있었다.

별도 후면 10초 독립 시험은 기본 문턱에서 10개 1초 구간 모두 추정 거부됐다. 원인 조사로 문턱을 모두 0으로 하자 10개 추정(168~198°)이 후면 180° ±30° 안에 있었으나, 상대 피크 구분도는 0.0024~0.0284로 기본 0.03보다 낮았고 잡음 오탐 검증이 없으므로 문턱 변경·실사용을 승인할 근거는 아니다. 독립 검증은 후면 한 위치뿐이며 신뢰도와 채널 배치 보정은 미완료다. 프로세스 재시작마다 기존 로그는 `/data/build/demo.log.before-step-*`에 보존했다. 캡처 후 원본 녹음은 임시 저장소에서 삭제했다.

## 2026-11-11 8채널 스트리밍 및 추가 실기 시험

보드의 `arecord` 8채널 PCM을 16진 텍스트로 인코딩해 ADB 셸로 보내고 Jetson에서 메모리에서 복원하는 제한 시간 진단 `tools/audio/r818_stream_probe.py`와 보드용 셸 스크립트를 추가했다. 기존 `demo`를 중단해 단독 점유해야 하므로 기존 음성 기능과 동시에 사용하지 못한다. 보드에서 사전 로그 백업 후 프로세스·watchdog 복구를 실행한다. 1초 8채널 블록을 약 1초 간격으로 받았고(첫 블록 시작 절차 포함 약 2.45초), 종단간 샘플 지연은 별도로 측정하지 않았다. 녹음은 저장하지 않았다.

정면·좌·우·후면 각 10초를 실기로 수신했다. 보정은 실험적이며 실기 정면은 314~348° 등 오차가 발생했고, 좌·우·후면에도 잘못된 후보가 있었다. 초기 2초를 억제하고 RMS 100, 공간 일치도 0.35를 조합한 환경 전용 진단 문턱을 추가했지만, 별도 후면 시험에서 조용해야 하는 구간에도 후보가 출력됐고(사용자는 큰 소리가 없었다고 확인, 안내와 캡처 시점 간 오차는 미측정), 후면 발화에서 134~148° 및 272° 등 변동이 관찰됐다. 이 문턱은 오탐과 방향 오차를 해결하지 못했으며 범용 음성 검출기나 로봇 제어에 사용하지 않는다. 기존 DOA 기본 문턱은 변경하지 않았다. 시험 종료 후 `demo` 및 내부 캡처 RUNNING, USB 모노 1초 입력을 확인했다.

## 2026-11-11 기존 음성 기능과 8채널 동시 접근 조사

기존 `CaptureDsnoop`으로 8채널 캡처 두 개를 동시에 여는 시험은 성공했다. 그러나 제조사 프로그램을 재시작하며 입력만 `CaptureDsnoop`으로 임시 전환한 경우 공유 캡처에는 사용자 음성이 있었지만 Jetson USB 모노는 매우 작았다. 별도 IPC 키를 사용하는 dsnoop 설정에서도 기대한 모노 신호를 확인하지 못했다. 원래 실행 방식으로 복구한 뒤에도 사용자 발화 시험에서 모노 RMS가 1초당 약 2~6 PCM 수준이어서 전환 자체가 원인인지 확정할 수 없다. 보드 캡처와 USB gadget 프로세스 상태는 RUNNING이지만, 정상 발화 음질 복구는 미확인이다.

기존 프로세스가 mmap 방식으로 8채널을 읽는 사실을 확인했고, 장치 소유를 유지한 채 해당 메모리를 비차단 FIFO로 복사하는 **임시 실험**에서 8채널 데이터가 Jetson에 도달했다. PCM 데이터는 저장하지 않았다. 하지만 동일 시험의 기존 모노 신호가 낮았고, FIFO 수신 종료 시 SIGPIPE 등으로 제조사 프로세스에 영향을 줄 위험과 데이터 누락 감지·연결 끊김 복구가 해결되지 않아 이 실험을 상시 적용하거나 완성 기능으로 채택하지 않았다. 모든 시험 후 원래 `demo`, `watch`, 내부 캡처 RUNNING 확인. 재시작 전 로그는 `/data/build/demo.log.before-coexist-*` 및 `/data/build/demo.log.before-share-probe-*`에 백업했다.

추가 근접 발화 시험에서 원래 모노 입력은 8개 1초 구간 중 마지막 2개 RMS가 41.3, 138.7 PCM, 전체 피크 780이었다. 신호 유입은 확인됐지만 이전 청취 상태 대비 정상 음량·음질을 입증할 수 없다. 안내 시각과 캡처 시작 시각의 차이가 있어 각 구간을 정확한 발화 여부로 해석하지 않는다.

## 2026-11-11 비차단 8채널 복사 및 방향 추가 시험

기존 `demo`가 캡처 장치를 계속 소유한 채 mmap PCM을 로컬 UNIX 데이터그램으로 비차단 복사하는 실험 코드 `tools/audio/r818_experiment/pcm_mirror.c`와 수신기 `packet_receiver.c`를 작성했다. 전송 실패 시 캡처를 막지 않고, 패킷 일련번호로 누락을 식별한다. ADB 수신기 두 차례 각 200패킷/51200프레임을 약 3.2초에 수신했고 연속 구간의 일련번호 누락은 0이었다. 이후 강제로 ADB 수신 연결을 끊었을 때 기존 `demo`가 살아 있었고, 남은 전용 소켓을 다음 수신기가 확인·정리한 뒤 200패킷 재수신했다. 최초 연결 전이나 연결 사이의 손실량·실시간 지연은 확인하지 않았다. 동일 소켓에 수신기 여러 개가 동시에 시작되는 경쟁 및 비정상 종료 전반은 미검증이다. 기존 프로세스를 임시 재시작해야 하며 지속 실행용 서비스는 아니다. 음성 기능의 음질과 장시간 성능은 검증하지 못했다.

별도 실기: 마이크에서 30~50cm 거리, 사용자 안내 후 4방향 발화, 실험 좌표(`calibrated=false`), 1초 비중첩 구간. 발화가 뚜렷한 구간의 원시 후보는 정면 주로 344~348°, 왼쪽 90~94°, 오른쪽 250~268°, 후면 148~154°였다. 일부 저신호 구간과 왼쪽 발화 중 168°, 후면 134° 등 오추정이 있었다. 정면 12~16°, 후면 26~32° 편향이 보이나 사용자 위치·정확한 발화 구간·마이크 좌표·환경 보정이 불확실하므로 정확도나 보정 완료로 판정하지 않는다. 각 방향 22개 1초 구간 수신에서 패킷 누락 0이었다. 이어서 조용한 환경 22초에서 원시 후보는 대부분 164~168°였으며 RMS 45.3~50.9, 공간 일치도 0.25~0.28이었다. 이는 특정 환경의 한 측정일 뿐 실외, 바람·모터·다른 목소리에서의 오탐률을 보장하지 않는다. 임시 RMS/공간 일치도 기준을 기본 DOA에 적용하거나 로봇 제어로 연결하지 않았다. 보드 원래 `demo`와 캡처 RUNNING 복구, 원본 음성 미저장.
