# 운영·센서 대시보드 데이터 계약

2026-11-15: 현재 구현과 이후 대시보드 작업에 적용할 목표 계약을 정리했다. 아래에 명시한 수신 시각 검증을 제외한 목표는 아직 구현 전이다. 현재 구현의 기준 파일은 `backend/ros_monitor.py`, `backend/app.py`, `frontend/src/main.jsx`다.

## 현재 데이터 흐름

ROS domain 25의 센서를 구독하는 모니터가 2초마다 `~/.local/share/jetinspect-ops/run/ros-status.json`을 원자적으로 갱신한다. FastAPI가 파일과 호스트·DB를 읽어 `/api/status`, `/api/metrics`, `/api/events`를 제공하고 React는 상태와 이벤트를 5초마다 조회한다. 모니터는 센서 데이터만 구독한다.

| 정보 | 현재 출처 및 단위 | 현재 유효성·표시 한계 |
|---|---|---|
| 호스트 | `/api/status.host`: CPU·메모리·디스크 %, 메모리·여유 공간 GiB, 온도 °C, `timestamp` UTC ISO 8601 | 요청 시 측정, 온도 미확인 시 null. 화면 하단 시각은 호스트 측정 시각이며 센서 수신 시각이 아니다. |
| 모니터 | 스냅샷 `timestamp`: Unix epoch 초; `/api/status.robot.status` | 파일 시각 차이가 `0 이상 8초 미만`이면 `monitoring`, 아니면 `monitor_unavailable`. 유효한 스냅샷만으로 개별 센서 수신을 보증하지 않는다. |
| 배터리 | `/battery_state`의 양의 유한 전압 V → `robot.battery_voltage` | 모니터는 마지막 수신 후 10초 미만일 때만 전압을 내보낸다. `battery_received_at`은 Unix epoch 초, `battery_age_seconds`는 API 조회 시 경과 초다. 시각이 없거나 미래·만료면 값은 null이다. |
| IMU·LiDAR·카메라 | `/imu/data_raw`, `/scan`, `/depth_cam/color/image_raw`; `robot.streams.{imu,scan,camera}.hz` Hz 및 `age_seconds` 초 | 최근 10초 수신 표본 중 두 개 이상으로 빈도 계산; 그렇지 않으면 Hz null. 나이는 마지막 수신 기준이며 없으면 null. `received_at`은 Unix epoch 초이고 화면은 경과 시간을 표시한다. 카메라 항목은 영상이 아닌 토픽 수신율이다. |
| DB·이력 | `database`: `connected` 또는 `unavailable`; `/api/metrics.samples` 최대 120건, `/api/events.events` 최대 50건 | 장애 시 각 이력 API는 `database: unavailable`, 빈 배열 반환. 이벤트 화면은 이력별 DB 장애와 빈 결과를 구분한다. |
| 서버 연결 | 브라우저의 HTTP 요청 | 상태 요청 실패 시 기존 데이터는 남고 경고를 표시한다. 상태·이벤트·이력 요청의 실패를 개별 표시하며 기존 센서 값은 경과 시간에 따라 만료된다. |

수신 시각과 호스트 시각은 현재 벽시계 기반이다. 이력 DB `recorded_at`은 DB가 생성하는 시간이며 타임존 표기가 API에서 보장되지 않는다. 정확한 시간대 변환은 DB 세션 설정 확인 전 단정하지 않는다.

## 구현할 목표 계약

- 기존 필드와 읽기 전용 엔드포인트의 호환성을 유지하면서 센서 측정 시각 또는 경과 시간, 스냅샷 시각, 자료 신선도를 명시한다. API 필드명과 null 처리의 최종 구현을 변경 시 함께 문서화한다.
- 스냅샷은 기존 `0 ≤ 경과 시간 < 8초`, 배터리와 센서 수신 자료는 기존 10초 창을 유지한다. 각각 모니터 2초 갱신과 현재 계산 방식에 맞춘 기존 기준이며 실기에서 검증된 임계값은 아니다. 추후 변경 시 측정 근거를 남긴다. 미래 시각·시간 역행·비정상 시각은 유효 측정값으로 표시하지 않는다.
- 모니터 미사용/만료, 센서 미수신 또는 측정 만료, 주파수 계산에 표본 부족, DB 장애, 이력 없음, 서버 연결 실패를 구분한다. 정확히 판별할 근거가 없으면 미확인으로 표시한다. 미수신은 로봇 고장·오프라인·안전을 뜻하지 않는다.
- 서버 조회 실패 시 이전 값을 보존한다면 이전 값임을 시간과 함께 표시한다. 재연결 시 최신 값으로 갱신한다. DB 조회 실패는 빈 결과와 별도로 표시하고 다른 유효 정보는 계속 표시한다.
- 센서 V·Hz·초, 호스트 %·GiB·°C와 시간대가 명확한 시각을 표시한다. 이력의 시간대는 확인해 명시하고 확인 전 로컬 시각으로 확정해 해석하지 않는다.
- 연결 실패·복구와 시간 경계 시험은 격리된 가짜 데이터로 수행한다. 모터·팔 명령, ROS publish/service/action, 센서 또는 로봇 기동은 추가하지 않는다.

2026-11-15 구현: 스냅샷에 `battery_received_at`과 각 스트림의 `received_at`을 추가하고 API에서 8초 스냅샷·10초 센서 유효성을 다시 검사한다. 시각이 없는 이전 모니터의 데이터는 호환을 위해 API 오류 없이 미확인으로 처리한다. 화면은 배터리 및 센서별 경과 시간과 표본 부족을 표시한다. 변경 적용에는 ROS 모니터와 대시보드 서비스 재시작이 필요하다.

2026-11-15 추가 구현: `/api/status.robot.snapshot_age_seconds`를 제공한다. 브라우저는 서버가 계산한 경과 시간에 요청 시작 이후 경과 시간을 더해 원격 장치 간 시계 차이와 응답 지연에 보수적으로 대응한다. 상태·이벤트·이력 오류는 별도로 표시한다.
